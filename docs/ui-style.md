# UI 스타일 규칙

[한국어](ui-style.md) | [English](en/ui-style.md)

공통 설계 원칙의 상위 출처는 [Tuivory](https://github.com/leechis7/tuivory)입니다. LazyOra 적용 기준과 마지막 확인 커밋은 [Tuivory 가이드 반영 기록](tuivory-sync.md)에 남깁니다. 아래 문서는 LazyOra의 실제 컴포넌트·단축키·상태 처리에 맞춘 적용 규칙입니다.

정식 v0.10.2 공통 스타일의 원본은 **Tuivory v0.0.1** (`github.com/leechis7/tuivory/go`)입니다. 단일 공개 패키지 `tuivory`의 `Styles`, `Styler`, `Choice`와 상태 스타일 메서드를 import합니다. `internal/ui/style_tokens.go`는 패키지 값과 제품 역할을 연결하고, `theme.go`·`widgets.go`는 공통 API를 기존 위젯에 적용합니다. 실제 의존 버전은 `go.mod`와 [적용 기록](tuivory-sync.md)에 고정합니다.
새 화면을 추가할 때 기본 tview 색상에 맡기지 않고 생성 시점부터 현재 테마를 적용합니다.

| 역할 | 공통 표시 |
| --- | --- |
| 일반 화면·본문·빈 공간 | 테마의 기본 배경과 본문 색상 |
| 목록·팝업 카드·폼 | 테마의 표면 배경. 목록의 본문·보조 설명·빈 행 배경도 동일 |
| 안내문·상태 설명 | 기본 배경 또는 카드 표면, 낮은 강조의 안내문 색상 |
| 텍스트 입력 | 밝은 입력 배경과 어두운 글자 |
| 선택박스 | 입력칸과 다른 선택 배경, ▾ 표시 |
| 체크박스 | 입력과 같은 정상 상태, 공통 선택 강조 |
| 일반 버튼·폼 버튼·확인창 버튼 | 같은 기본 버튼 색과 포커스 스타일 |
| 포커스된 박스 | 이중선·강조색. 비포커스는 단일선·차분한 색; ANSI 굵기는 포커스의 필수 조건이 아님 |
| 팝업 | 중앙 배치·내부 여백·어두워진 배경·배경 클릭 차단, 작은 창에서는 축소·스크롤 |

팝업 카드 영역은 자식 위젯을 그리기 전에 불투명 표면색으로 채웁니다. 여백과 버튼 사이에도 배경의 글자·테두리·어두워짐 효과가 비치면 안 됩니다.
8색·16색·256색·True Color 프로필을 구분합니다. 8색은 0~7, 16색은 0~15의 명시적 팔레트, 256색은 전용 인덱스, True Color는 RGB를 사용합니다. 큰 배경은 중립색을 유지하며, 다크 8색의 강조는 어두운 노랑, 다크 16색은 청록 계열, 라이트는 진한 파랑 계열을 사용합니다. 사용자 ANSI 팔레트의 실제 RGB는 단말마다 다릅니다.
흑백 테마(`blackwhite`)는 색상 수에 관계없이 무채색만 사용합니다. SQL 키워드·바인드는 밑줄, 주석은 기울임, 선택·활성 셀·버튼은 전경/배경과 밑줄, 포커스된 박스는 이중선으로 구분합니다. 검정 글자에 굵기를 적용해 회색으로 바뀌는 조합을 피합니다.
라이트 편집기는 True Color에서 RGB 흰색, 256색에서 인덱스 231의 흰색을 사용합니다. 8/16색의 흰색 밝기는 실제 터미널 팔레트에 따릅니다.

SQL 편집기는 편집용 배경과 문법 강조, 결과 그리드는 헤더·현재 셀·범위·NULL 등 자료 표현 규칙을 사용합니다.
상단 메뉴·SQL 탭·하단 단축키·경고도 각 역할의 공통 팔레트를 사용합니다.

공통 진입점:

- 본문·안내·강조 텍스트: `s.newTextView()` / `textHint` / `textAccent`
- 컨테이너와 빈 공간: `s.newFlex()`, `s.newBox()`
- 다른 배경의 글/상자: `s.textSurface(view, role)`, `s.setSurface(box, role)` — 과거 색상 값 대신 배경 역할을 기록
- 객체·인자·스크립트 등 일반 상세 표: `s.newDataTable()` — 초기 그리기부터 헤더·본문·빈칸을 공통 역할로 표시
- 목록: `s.styleList()` — 배경·주/보조 글자·선택·바로가기 색상
- 트리 항목: `s.newTreeNode()` — 본문·강조 색상과 공통 선택 스타일
- 입력·폼·선택·체크박스: `s.newInputField()`, `s.styleForm()`, `s.newChoice()`, `s.styleCheckbox()`
- 일반 버튼·확인창: `s.clickable()`, `s.styleModal()`
- 중앙 팝업: `s.formDialog()` 또는 `s.formPopup()`
- 상단·우클릭 메뉴: 메뉴 영역만 그리며 바깥 공간은 투명하게 유지합니다. 배치용 빈 공간을 Box로 채워 뒤쪽 작업 화면을 지우지 않습니다.
- 포커스 테두리: `s.refreshBorders()` — 화면별 별도 강제 테두리 처리 금지

테마 변경은 `theme_apply.go`에서 과거 색상을 추측하거나 치환하지 않고 현재 역할을 재적용합니다. 기존 위젯에 적용하여 입력값·SQL·결과·선택·포커스·스크롤을 보존합니다.
텍스트 배경은 Box와 TextView 렌더러를 함께 갱신합니다. 본문·안내문·강조문 역할도 유지합니다.
닫힌 화면의 텍스트 역할 정보는 다음 그리기 전에 정리하여 화면을 계속 보관하지 않습니다.

검증은 다크·라이트·흑백 × 8/16/256색·True Color의 12조합, 새 화면·테마 변경 후 화면,
키보드·마우스·작은 터미널을 포함합니다. 공통 규칙 수정 시 도움말뿐 아니라
접속·설정·출력·이력·계획·스크립트·객체·편집·확인창도 회귀 검사합니다.

## 적용 완료와 설계 기록

LORA-69의 추가 조사로 [공식 자료를 반영한 스타일 가이드 제안](ui-style-proposal.md)과 [색상 후보표](ui-style-palette-candidate.csv)를 준비했습니다. 설계안의 공통 프로필·폼/버튼·배경 역할·표·SQL 문법색·테마 재적용을 로컬 코드에 반영했습니다. 후보 CSV는 초기 검토 자료이며 실제 팔레트의 기준은 고정한 Tuivory 패키지입니다. `style_tokens.go`는 값·역할 어댑터이며 팔레트 원본이 아닙니다. 독립 패키지 추출·공개·LazyOra import 전환은 완료했고, 실제 사용자 단말의 확대 확인은 별도입니다.

독립 Tuivory 프로젝트의 개발과 가이드는 [Tuivory 저장소](https://github.com/leechis7/tuivory)에서 관리합니다. 이 저장소의 [초기 준비 자료](tui-style-guide/README.md)는 유래 기록으로 보존하며, 현재 반영 상태는 [가이드 반영 기록](tuivory-sync.md)을 기준으로 확인합니다.

미커밋 셀은 배경색 외에 행 번호의 `*`와 선택 셀 상태 문구로 식별합니다. 선택 범위가 수정 배경을 덮더라도 변경 사실을 확인할 수 있고, 복사/내보내기 값에는 표식을 넣지 않습니다.

## 새 트리 적용 (개발 중)

개발 브랜치는 Tuivory v0.1.0의 공개 `Tree`·`TreeState`·`TreeView`를 사용합니다. 기존 `NewStyles`의 의미별 색을 새 트리의 body/hint/surface/selection/focus.border 역할로 연결하며 별도 후보 팔레트를 혼합하지 않습니다. Oracle 메타데이터·노드 식별·지연 조회·상세 열기와 기존 포커스 이중선은 LazyOra가 관리합니다. 정식 v0.10.2의 스타일·바이너리는 변경하지 않았습니다.

LORA-78 개발 변경은 공통 Tuivory v0.1.0 트리의 ASCII 옵션과 LazyOra의 화면 전용 어댑터를 연결합니다. 문자 모드는 테마·색상 프로필·마우스와 독립적입니다. ASCII에서는 영어 UI를 사용하고 단일/이중 가로선을 -/=로 구분하며 비 ASCII 데이터의 대체 표시는 편집·복사·내보내기 원문을 바꾸지 않습니다. 기존 패키지 소스를 변경하거나 복사하지 않습니다.
