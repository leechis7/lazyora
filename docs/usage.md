## DBMS_OUTPUT 출력

**Alt+P / 보기 → DBMS_OUTPUT 출력**에서 출력 창을 열고, SQL 실행 전에 **Alt+E / 출력 켜기**를 누릅니다. 세션 메뉴에서도 켜기·끄기를 선택할 수 있습니다. F9 SQL·PL/SQL과 F5 스크립트를 실행하면 문장 완료 후 출력을 수집합니다. 실행 중 실시간 출력은 Oracle DBMS_OUTPUT의 동작상 제공하지 않습니다.

출력 창의 **Ctrl+C**는 보관한 원문 전체를 복사하고 **Alt+D**는 표시만 지웁니다. 빈 줄·한글·색상 태그 모양 문자열도 원문대로 유지합니다. 방향키·PgUp/PgDn으로 스크롤하고 Tab으로 출력과 버튼을 이동합니다. Esc는 출력 창을 닫으며 실행 중인 SQL을 취소하지 않습니다. SQL 오류가 나도 오류 전 출력 수집을 시도하고, 출력 수집 실패는 SQL 처리 결과와 별도로 표시합니다.

서버 버퍼는 1,000,000바이트입니다. 문장당 최대 2,000행·256 KiB를 수집하고 남은 출력은 버려 다음 SQL 출력과 섞이지 않게 합니다. 화면에는 최근 8,000행·1 MiB를 보관하며 생략 여부를 안내합니다. 수집은 별도 3초 제한으로 수행합니다. 서버 버퍼·행 길이 제한 초과는 SQL 자체 오류가 될 수 있으며, 지원 버전의 세부 제한은 [Oracle 문서](https://docs.oracle.com/en/database/oracle/oracle-database/18/arpls/DBMS_OUTPUT.html)를 참고하세요.

출력 제어·조회는 커밋·롤백하거나 미커밋 SQL 기록을 추가하지 않습니다. 재접속하면 새 세션의 출력은 꺼지고 화면 기록도 초기화합니다. 출력 수집 실패 후 다음 SQL 전에 남은 서버 버퍼를 비우며, 그 정리에 실패하면 SQL을 실행하지 않고 안내합니다. Oracle Free에서 한글·30KB 행·스크립트·출력 제한 및 DML 보존을 검증하며, 구형 Oracle에서 실제 지원하는 행 길이·권한 제약은 따릅니다.

## 메뉴에서 기능 찾기

- **파일**: SQL 파일 열기·저장·다른 이름으로 저장, 종료
- **SQL 탭(Alt+G)**: 새 SQL 탭, 현재 탭 닫기, 다음·이전 탭
- **편집**: 실행 취소·다시 실행, 잘라내기·복사·붙여넣기·SQL 전체 선택, 결과 행 복사·내보내기, 찾기·바꾸기
- **세션 / 실행**: 접속, 커밋·롤백·미커밋 내역, SQL·스크립트 실행·실행 계획·취소
- **보기**: 실행 내역·이력, 전체화면·포커스 이동, 스키마 선택·새로고침·객체 정보
- **도구 / 도움말**: 설정·암호 관리, F1 도움말

편집 메뉴는 메뉴를 열기 직전의 포커스와 선택 범위를 사용합니다. SQL 편집 기능은 쿼리창에서, 결과 행 복사는 결과창에서 활성화됩니다. **복사한 내용 붙여넣기**는 앱에서 복사·잘라낸 내용을 삽입합니다. OS 클립보드의 내용은 터미널의 붙여넣기 기능으로 입력하세요. 긴 메뉴는 방향키로 끝까지 스크롤할 수 있습니다.

## 연결

일반 실행 시 접속 화면이 먼저 열립니다(`--demo`는 메인 화면으로 시작). **Alt+L** 또는 **세션 → 접속**(Alt+S, Enter)으로 다시 열어 Host, Port, Username, Password를 입력합니다. 연결 유형에서 **Service Name** 또는 **SID**를 선택하고 해당 이름을 입력한 뒤 **Ctrl+Enter / Alt+C** 또는 접속 버튼 클릭으로 연결합니다. 암호는 화면에서 가리며, 기본적으로 디스크에 저장하지 않습니다. 명시적으로 암호화 저장을 선택할 수 있습니다. 선택적으로 `LAZYORA_HOST`, `LAZYORA_PORT`, `LAZYORA_USER`, `LAZYORA_PASSWORD`, `LAZYORA_NAME` 환경변수로 입력 기본값을 지정할 수 있습니다. 암호를 명령행 인자로 받지 않습니다.

직접 입력칸은 **흰 배경**, 선택박스는 **어두운 파랑 계열 배경과 `v` 표시**로 구분합니다. 선택박스에 포커스가 있으면 청록색으로 강조합니다. 8·16색 터미널에서는 선택박스에 ANSI 파랑을 사용합니다.

접속 화면 위쪽 **저장된 접속 불러오기**에서 기존 프로필을 선택합니다. 아래 **접속 정보 편집**은 **별칭(Alias)**부터 시작합니다. **Alt+R**은 저장된 접속, **Alt+A**는 별칭으로 이동하며 **Tab/Shift+Tab**은 두 영역을 순환합니다. 목록의 **새 접속**을 선택하면 환경변수·기본값으로 돌아가고 비밀번호는 비웁니다.

**별칭(Alias)**을 입력하고 하단 **저장(Ctrl+S / Alt+S)** 버튼을 누르면 호스트·포트·사용자·접속 방식·Service Name/SID를 저장합니다. 실제 DB에 연결하지 않아도 저장할 수 있습니다. 같은 별칭은 기존 정보를 갱신하고, 다른 별칭은 새 접속으로 추가합니다. 다음 실행에서 **저장된 접속(Alt+R)** 목록으로 불러올 수 있으며 **Alt+A**로 별칭 입력칸을 선택합니다. 별칭을 바꾸어 저장하면 새 항목이 추가됩니다.

접속 정보는 UI 설정 파일과 같은 폴더의 `connections.json`에 저장합니다. Linux 기본 경로는 `~/.config/lazyora/connections.json`입니다. 기본적으로 **비밀번호는 저장하지 않습니다.** 저장된 접속을 선택하면 이전 비밀번호를 지우고, 암호화 저장을 사용한 접속만 잠금 해제 후 해당 비밀번호를 채웁니다. 저장 버튼을 누를 때는 현재 입력한 비밀번호를 메모리에 유지하여 바로 접속할 수 있습니다. **비밀번호 저장 (암호화)**을 선택하고 저장하면 별도 암호화 저장소에 보관합니다. **Alt+K** 또는 **도구 → 암호 관리**에서 잠금·마스터 변경·초기화를 할 수 있습니다. 자세한 사용법은 [암호 관리](credentials.md)를 참고하세요.

여러 인스턴스가 같은 접속 목록을 사용하면 저장 전에 변경 충돌을 검사합니다. **다른 인스턴스가 저장 중**이면 잠시 후 재시도하고, **목록 변경** 안내가 나오면 접속 창을 다시 열어 최신 목록을 확인한 뒤 저장하세요. 충돌이 발생한 창의 입력은 유지하며 저장된 파일은 덮어쓰지 않습니다.

## SQL 구문 색상

SQL 탭과 PL/SQL 소스 편집기는 키워드(파랑), 기본 함수(청록), 타입·숫자(보라), 문자열(빨강), 주석(초록), 바인드(갈색)를 구분합니다. Oracle q/nq 인용·여러 줄 주석과 작성 중인 미완성 문자열도 표시합니다. 흰 입력 배경과 선택 강조는 유지하며 8·16색에서는 ANSI 색상으로 표시합니다. 색상은 화면에만 적용하므로 저장·복사·SQL 실행 원문에는 태그나 제어 문자를 추가하지 않습니다. 객체·컬럼 자동 완성은 별도 후속 작업입니다.

## 언어·마우스 설정

한 실행파일에서 English와 한국어를 지원합니다. **도구 → 설정**(Alt+T, Enter)에서 언어와 마우스 사용 여부를 선택하고 **Ctrl+S / Alt+S** 또는 저장 버튼으로 적용합니다. Esc는 변경을 취소합니다. 언어를 바꿔도 작성한 SQL, 조회 결과와 접속 화면의 입력값을 유지합니다. Oracle에서 받은 오류와 조회 데이터는 원문을 표시합니다.

저장된 언어 설정이 없으면 `LC_ALL`, `LC_MESSAGES`, `LANG` 순서로 처음 발견한 비어 있지 않은 값을 확인합니다. `ko` 로캘이면 한국어, 나머지는 영어입니다. 설정 파일 없음·언어 항목 누락·빈 값·null을 미설정으로 처리하며, 명시적으로 저장한 한국어·영어 설정은 로캘보다 우선합니다. 마우스는 기본으로 켜져 있습니다. 버튼·입력칸·결과 셀을 클릭하고 휠로 스크롤할 수 있습니다. 마우스를 껐을 때도 도구 → 설정에서 다시 켤 수 있습니다.

설정은 OS 사용자 설정 폴더의 `lazyora/settings.json`에 저장합니다. Linux 기본 경로는 `~/.config/lazyora/settings.json`이며 `XDG_CONFIG_HOME`을 따릅니다. `LAZYORA_CONFIG`로 파일 경로를 지정할 수도 있습니다. 언어와 마우스 설정만 저장하며 접속 정보는 같은 폴더의 별도 파일로 관리합니다. `LAZYORA_CONFIG`의 파일 이름을 `connections.json`으로 지정했다면 접속 파일 이름은 충돌을 피하도록 `connection-profiles.json`을 사용합니다. `Connections.json`·`CONNECTIONS.JSON`처럼 대소문자만 다른 경우도 모든 OS에서 같은 규칙을 적용하며 파일 생성 전후 경로가 바뀌지 않습니다. DB 비밀번호는 설정·접속 프로필 JSON에는 저장하지 않으며, 선택한 경우 별도 `credentials.enc`에 암호화하여 저장합니다. 저장에 실패하면 기존 설정을 유지하고 오류를 표시합니다.

이전 버전의 대소문자 구분 Linux 파일시스템에서 `Connections.json` 같은 설정명과 별도 `connections.json` 프로필을 함께 사용했다면 이제 `connection-profiles.json`을 읽습니다. 기존 파일을 자동 이동하거나 합치지 않습니다. 같은 폴더를 사용하는 앱을 모두 종료하고 백업한 뒤 기존 **프로필 JSON**을 새 경로로 옮기세요. 대상 파일이 이미 있으면 덮어쓰지 말고 두 목록을 검토해야 합니다. 기본 `settings.json`을 쓰는 경우에는 파일명 변경이 없습니다.

## 스키마·객체 탐색

접속하면 왼쪽 브라우저 위에 **사용자·객체 종류 선택박스**, 아래에 **객체 목록**이 나타납니다. 기본 사용자는 접속 계정, 기본 종류는 테이블입니다. 사용자를 바꾸면 해당 사용자의 객체를 조회하고 종류를 바꾸면 해당 종류만 표시합니다. **Alt+U 사용자**, **Alt+O 객체 종류**로 이동하며 마우스로도 선택할 수 있습니다. 스키마 목록에는 `ALL_USERS`에 보이는 계정이 표시되지만 객체는 현재 접속 계정에 접근 권한이 있는 항목만 표시하므로 빈 스키마도 있을 수 있습니다. 탐색으로 접속 계정이나 현재 스키마를 변경하지 않습니다.

지원하는 분류는 **테이블, 뷰, 구체화 뷰, 함수, 프로시저, 패키지, 패키지 본문, 시퀀스, 동의어, 인덱스, 트리거, 타입, 타입 본문**의 13종입니다. 구체화 뷰의 저장용 테이블은 테이블 분류에 중복 표시하지 않습니다. 패키지·타입의 정의와 본문은 별도 분류로 표시합니다.

**Alt+B** 또는 **보기 → 스키마**로 스키마 창을 표시하거나 숨깁니다. 숨기면 SQL·결과 영역이 전체 너비를 사용하고, 다시 열면 기존 사용자·종류·목록·선택 상태를 유지한 채 탐색기로 포커스를 옮깁니다. 방향키 위·아래로 선택하고 **Enter 또는 클릭**으로 객체 상세를 엽니다. 테이블·뷰·구체화 뷰를 열면 컬럼명·데이터 타입·NULL 허용 여부·컬럼 코멘트를 별도 화면에서 확인합니다. 코멘트가 없는 컬럼은 빈칸으로 표시합니다. 그 밖의 객체는 스키마·이름·종류·상태를 보여줍니다. 함수·프로시저·패키지/본문·타입/본문·트리거는 **Alt+S**로 소스를 조회·편집합니다. 함수·프로시저·패키지/본문은 **Alt+A**로 인자·반환값·오버로드를 확인합니다. 소스 화면의 **F9** 또는 컴파일 버튼으로 수정 내용을 DB에 적용하거나 기존 객체를 재컴파일하고, 오류의 행·열·메시지를 확인합니다. 컴파일 전에는 DDL의 암시적 커밋을 경고하며, 적용하지 않은 편집 내용을 닫기·새로고침·종료로 버릴 때도 확인합니다. 마우스 휠로 목록을 스크롤할 수 있습니다.

탐색기에서 **Ctrl+R**은 스키마 목록과 선택 스키마의 객체를 새로 불러옵니다. 객체 상세에서는 **Ctrl+R**로 컬럼 또는 기본 정보를 다시 조회하고 **Esc** 또는 닫기 버튼으로 돌아옵니다. **Tab**은 SQL → 결과 → 표시 중인 사용자 선택 → 객체 종류 선택 → 객체 목록 순서로, **Shift+Tab**은 역순으로 이동합니다. 스키마 창이 숨겨져 있으면 포커스 이동 대상에서 제외합니다. F6으로 SQL과 결과 사이를 전환할 수도 있습니다.

탐색과 컬럼 상세는 작성 중인 SQL·조회 결과와 미완료 트랜잭션을 유지합니다. 메타데이터 조회도 기존 SQL 실행과 같은 백그라운드 작업으로 순서대로 처리하며 Esc로 취소를 요청할 수 있습니다. `--demo`에서는 DB 없이 샘플 객체 목록과 컬럼 상세를 살펴볼 수 있습니다. Oracle 10g에도 있는 사전 뷰의 컬럼을 사용했으며, 이번 기능의 실DB 검증은 Docker Oracle Free에서 진행했습니다.

## SQL 파일

**Ctrl+O 열기**, **Ctrl+S 저장**, **Ctrl+Shift+S 다른 이름으로 저장**, **Ctrl+N 새 SQL 탭**, **Ctrl+W 닫기**를 지원합니다. 파일 열기·저장은 **파일** 메뉴, 새 탭·닫기·다음·이전 탭은 **SQL 탭(Alt+G)** 메뉴에서도 선택할 수 있습니다. Ctrl+Shift+S를 구분하지 못하는 터미널에서는 **파일 → SQL 다른 이름으로 저장**을 사용하세요. Ctrl+N은 새 탭을 열고 Ctrl+W는 현재 탭을 닫습니다. 마지막 탭을 닫으면 빈 탭 하나를 유지합니다. **Ctrl+Tab / Ctrl+Shift+Tab** 또는 터미널 대체 키 **Alt+PgDn / Alt+PgUp**으로 전환하며 상단 탭을 클릭할 수도 있습니다. 탭이 많으면 활성 탭 주변 4개와 이전/다음 버튼을 표시합니다. 각 탭의 편집기·커서·선택·스크롤·조회 결과를 유지합니다. **탭은 하나의 DB 연결·트랜잭션을 공유**하므로 한 탭의 커밋·롤백이 모든 탭에 적용됩니다. 실행 중에는 새 탭·탭 전환·닫기를 잠가 결과의 귀속을 유지합니다. 앱 종료 시 모든 수정 탭을 차례로 확인합니다.

파일 창에서 경로를 입력하거나 디렉터리·파일 목록을 선택합니다. 디렉터리는 Enter·클릭으로 이동하고 파일을 선택하면 경로를 채웁니다. 경로 입력 중 Enter, **Ctrl+Enter / Alt+Enter**, 또는 열기·저장 버튼으로 적용합니다. **Tab / Shift+Tab**은 경로·목록·버튼 사이를 이동하고 버튼은 좌우 방향키로 선택합니다. Esc는 취소하며 F1은 도움말입니다. 상대 경로는 현재 탐색 중인 디렉터리를 기준으로 하고 `~/`도 사용할 수 있습니다.

SQL 창 제목에 파일명과 **미저장 표시 `*`**가 나타납니다. 수정한 SQL을 다른 파일 열기·닫기·종료로 버리기 전에는 **저장 / 버리기 / 취소**를 확인합니다. 기본 선택과 Esc는 취소입니다. 저장 경로 선택이나 덮어쓰기를 취소하거나 저장에 실패하면 후속 작업을 진행하지 않고 편집 내용을 유지합니다. 앱 종료는 SQL 파일 확인 후 기존 DB 종료 확인으로 이어집니다. **파일 저장은 DB 커밋이 아니며**, 파일을 버리는 선택도 DB 롤백을 실행하지 않습니다. 뒤의 DB 종료창에서 계속 사용을 선택하면 SQL 편집 내용도 유지합니다.

한글을 포함한 **UTF-8 SQL 파일(최대 16 MiB)**을 지원합니다. UTF-8 BOM과 LF·CRLF 형식을 보존하며, 줄바꿈이 섞인 파일을 수정하여 저장하면 첫 줄바꿈 형식으로 통일합니다. 수정 없이 같은 파일을 저장하면 원본 바이트를 유지합니다. NUL이 있는 파일·잘못된 UTF-8·심볼릭 링크는 열지 않습니다. 기존 파일 덮어쓰기와 외부 수정·삭제 감지는 별도 확인을 거칩니다. 외부 프로그램의 저장과 완전히 동시에 발생한 변경까지 잠그지는 않습니다.

저장은 같은 디렉터리의 임시 파일을 작성한 뒤 교체하며, 기존 파일의 권한 비트를 유지하고 새 파일은 소유자 읽기·쓰기 권한으로 만듭니다. 부모 디렉터리는 미리 있어야 합니다. 읽기 전용 파일·잘못된 경로·쓰기 실패는 오류를 표시하며 편집 내용을 유지합니다. 다른 LazyOra의 동시 저장은 `<파일명>.lazyora.lock`으로 막습니다. 비정상 종료 후 이 파일이 남아 저장이 막히면 해당 파일을 저장 중인 LazyOra가 없는지 확인한 뒤 잠금 파일만 제거하세요.

## 바인드 변수

F9·Ctrl+Enter·F5의 실행 대상에 `:name` 또는 `:1` 같은 변수가 있으면 타입·값·NULL을 입력합니다. 주석·문자열·따옴표 식별자·q/nq 인용과 PL/SQL `:=`는 변수로 세지 않습니다. 같은 이름은 대소문자를 구분하지 않고 한 번 입력하며, 스크립트 전체에서도 같은 값을 사용합니다. 서로 다른 변수는 최대 32개입니다.

최초 지원 범위는 **IN 전용 문자열·NUMBER·DATE·TIMESTAMP·NULL**입니다. NUMBER는 소수점 `.`·지수 표기와 Oracle의 38자리 정밀도/범위를 지원합니다. DATE는 `YYYY-MM-DD`, TIMESTAMP는 `YYYY-MM-DD HH:MM:SS[.소수초]`로 입력합니다. NULL을 선택하면 값 칸을 무시합니다. 따옴표로 감싼 변수명·OUT·IN OUT·REF CURSOR는 미지원이며, INTO/대입 출력 변수는 사전 거절합니다. 프로시저 인자의 방향을 사전 조회하지 않으므로 IN 호출만 사용하세요.

Ctrl+Enter·Alt+Enter 또는 실행 버튼으로 적용하며 Esc는 DB에 제출하지 않고 취소합니다. 변환 오류가 있으면 창을 유지합니다. 값은 SQL 문자열로 치환하지 않고 **드라이버 바인드 인자**로 전달합니다. 위험 SQL 확인과 바인드 입력은 실행 대상 원문을 유지합니다.

각 탭의 최근 실행 SQL이 동일할 때만 직전 값을 메모리에서 다시 채웁니다. **기억한 값 지우기**는 모든 탭의 기억 값을 지우며, 성공적인 재접속·탭 닫기·앱 종료 때도 제거합니다. 값은 SQL 이력·미커밋 SQL 원문·설정·파일에 저장하지 않습니다. 서버 오류·조회 결과에는 Oracle이 반환한 값이 포함될 수 있습니다.

## F5 스크립트 실행

F5 또는 실행 메뉴의 **스크립트 실행**으로 선택 영역(없으면 전체 편집기)을 실행합니다. 문장을 순서대로 실행하기 전에 전체 원문과 트랜잭션 주의사항을 확인합니다. 기본 선택과 Esc는 취소입니다. 일반 SQL은 세미콜론, PL/SQL·저장 객체 단위는 별도 줄 `/`로 구분합니다. 마지막 PL/SQL 단위는 `/`를 생략할 수 있습니다.

스크립트는 **최대 100문장, 전체 60초**이며 첫 오류·취소에서 중단합니다. Esc는 실행 취소를 요청합니다. 앞서 성공한 DML을 자동 롤백하지 않으며, 스크립트 안의 기본 `COMMIT [WORK]`·`ROLLBACK [WORK]`은 공유 DB 세션의 트랜잭션을 처리합니다. DDL·PL/SQL의 암시적/내부 커밋도 Oracle 동작을 따릅니다. `ROLLBACK TO`, SQL*Plus 명령(SET SERVEROUTPUT·SPOOL·PROMPT·@ 등), `&` 치환 변수는 미지원입니다. 미지원 명령·잘못 닫힌 입력은 전체 실행 전에 검사합니다. DBMS_OUTPUT 수집은 아직 지원하지 않습니다.

완료·오류 후 문장별 원래 시작 행·성공/오류·조회/변경 행 수와 SQL 원문을 보여줍니다. 방향키로 문장을 선택하고 Tab으로 원문·조회 결과·버튼을 이동합니다. 여러 SELECT 결과는 각각 최대 1,000행을 보관하며 잘림은 `+`로 표시합니다. 마지막 SELECT 결과를 메인 결과창에 표시하고, 다른 결과는 **선택 결과를 결과창으로** 버튼으로 가져올 수 있습니다. **보기 → 스크립트 실행 내역**에서 해당 탭의 최근 실행 내역을 다시 엽니다. Ctrl+C는 실행 요약을 복사합니다. 출력·결과·제출 이력은 현재 실행 중인 앱의 메모리에만 보관합니다.

## 예상 실행 계획

**Ctrl+E / 실행 → 실행 계획**은 선택 SQL(없으면 커서 문장)의 예상 계획을 조회합니다. [Toad의 Ctrl+E 배정](https://support.quest.com/toad-for-oracle/kb/4297441/explain-plan-with-ctrl-e-gives-error-ora-00933-sql-command-not-properly-ended)을 따릅니다. SELECT/WITH/INSERT/UPDATE/DELETE/MERGE 한 문장을 지원하며 원 SQL을 실행하지 않습니다. 바인드가 있으면 기존 입력창을 사용합니다. 실제 실행 통계·캐시 커서 계획은 제공하지 않으며, 바인드가 든 예상 계획은 실제 실행 계획과 다를 수 있습니다.

트리에서 방향키·클릭으로 Operation/Options·객체·Cost·Rows를 선택하고 Enter로 펼치거나 접습니다. Tab으로 상세 조건식(Access/Filter)·원문 영역과 닫기 버튼으로 이동합니다. Ctrl+C는 상세를 복사하고 Esc는 닫습니다. 편집기와 기존 조회 결과를 유지합니다.

접속 계정에 **PLAN_TABLE 및 INSERT/SELECT/DELETE 권한**이 필요합니다. 없는 경우 오류를 표시하며 테이블을 자동 생성하지 않습니다. 같은 세션·트랜잭션에서 임의의 statement_id로 계획을 만들고 해당 행만 지웁니다. 기존 DML을 커밋·롤백하지 않고 앱의 미커밋 실행 기록에도 계획용 작업은 추가하지 않습니다. Oracle의 EXPLAIN PLAN은 DML이며 병렬 DML 사용 조건 등에 영향을 줄 수 있습니다. [Oracle SQL Reference](https://docs.oracle.com/en/database/oracle/oracle-database/18/sqlrf/EXPLAIN-PLAN.html)와 [Oracle 10g 계획 안내](https://docs.oracle.com/cd/B12037_01/server.101/b10752/ex_plan.htm)를 참고하세요. Oracle 10g에 있는 컬럼을 사용하고 Oracle Free에서 미커밋 DML 보존을 검증했습니다.

## 조회 결과 내보내기

결과창의 **우클릭 → 조회 결과 내보내기**, **편집 → 조회 결과 내보내기**, **Ctrl+Shift+E / Alt+W**로 엽니다. CSV·TSV·Excel(.xlsx)·Oracle INSERT(.sql), 저장 경로, **가져온 결과 전체 / 선택한 사각 범위 / 현재 행 / DB 전체 결과 (재조회)**을 지정합니다. Ctrl+S·Ctrl+Enter·저장 버튼으로 적용하며 실행 중 Esc는 저장을 중단합니다. 실패·취소하면 기존 파일과 SQL·조회 결과·DB 트랜잭션을 유지합니다. 덮어쓰기는 기본 취소 확인창을 거칩니다.

기본값인 **가져온 결과 전체**와 선택 범위·현재 행은 화면에 이미 가져온 결과만 저장합니다(최대 1,000행·파일 64 MiB). **DB 전체 결과 (재조회)**를 선택하면 해당 결과를 만든 원래 SELECT와 당시의 IN 바인드 값으로 다시 조회하며, 행을 읽는 대로 파일에 기록합니다. 현재 편집기의 SQL이나 나중에 입력한 바인드 값으로 바꿔 실행하지 않습니다. DB 드라이버의 묶음 조회와 공통 256 KiB 파일 쓰기 버퍼를 사용합니다. 전체 결과를 메모리에 누적하지 않으며, 앱의 행 수·64 MiB 파일 크기·60초 시간 제한을 적용하지 않습니다. DB·드라이버·네트워크의 제한과 단일 셀 크기·지원 타입 제한은 계속 적용됩니다.

재조회는 **원 SQL과 대상 파일을 보여주는 확인창**을 거치며 기본 선택은 취소입니다. 다시 조회한 시점의 데이터이므로 화면 결과와 달라질 수 있고, SQL 안의 사용자 함수가 부작용을 일으킬 수도 있습니다. 같은 DB 세션·공유 트랜잭션을 사용하며 미커밋 변경도 해당 세션의 조회 규칙을 따릅니다. 자동 COMMIT/ROLLBACK은 수행하지 않습니다. `SELECT FOR UPDATE`는 전체 결과 재조회를 지원하지 않습니다. 바인드 값 지우기·재접속 후에는 이전 탭·스크립트 결과의 재조회 정보를 제거하므로 SELECT를 다시 실행해야 합니다. 이 경우에도 화면에 가져온 결과 저장은 가능합니다. 재조회 시 컬럼 목록이 달라졌다면 중단하고 다시 실행하도록 안내합니다.

저장 중 처리 행 수를 표시하고 **Esc로 취소를 요청**합니다. 원본 화면 결과·SQL은 유지하며 임시 파일을 끝까지 작성하고 커서를 닫은 뒤에만 대상 파일을 교체합니다. 읽기·쓰기·커서 종료 오류나 취소가 발생하면 기존 파일은 보존하며 부분 파일을 성공으로 처리하지 않습니다. DB 드라이버·서버 상태에 따라 취소 응답에 시간이 걸리거나 연결 상태를 다시 확인해야 할 수 있습니다. 완료하면 실제 저장 행 수와 경로를 표시합니다. 스크립트의 다른 SELECT는 실행 내역의 결과를 메인 결과창으로 가져온 후 내보낼 수 있습니다. 원본 값과 실제 NULL 정보를 사용하며 화면의 잘림·색상·테두리는 포함하지 않습니다.

- **CSV·TSV:** UTF-8, 선택적 BOM·헤더, 구분자·따옴표·줄바꿈 인용을 지원합니다. NULL 표시는 기본 `\N`이며 바꿀 수 있습니다. 빈 문자열은 빈 필드입니다. 스프레드시트의 CSV 자동 형식 추론은 통제하지 않으므로 정밀도·앞자리 0·수식 모양 텍스트를 보존하려면 XLSX를 사용하세요.
- **Excel:** 실제 .xlsx의 `Results` 시트에 기록하고, 시트당 1,048,576행에 도달하면 `Results_2`, `Results_3` 등으로 자동 분할합니다. 헤더를 선택하면 매 시트에 반복하며 헤더도 행 수에 포함합니다. 숫자·날짜를 포함한 모든 비NULL 값을 **텍스트 셀**로 저장해 15자리 이후 숫자, 앞자리 0, 한글, 수식 모양 텍스트를 보존합니다. NULL은 비어 있는 셀로 둡니다. Excel의 16,384열·셀당 32,767 UTF-16 단위 및 XML 문자 제한을 넘으면 기존 파일을 바꾸지 않고 오류를 표시합니다.
- **INSERT:** 대상 테이블은 필수이며 쿼리에서 임의 추정하지 않습니다. 스키마는 선택이고, **대상 컬럼(CSV)**에서 컬럼별 매핑을 수정합니다. 컬럼 수는 내보낼 컬럼 수와 같아야 하며 실제 DB 컬럼명의 대소문자를 입력합니다. 기본값은 조회 컬럼명·별칭이므로 계산식·별칭·조인 조회는 반드시 실제 대상 컬럼으로 고치세요. 스키마·테이블은 일반 이름을 대문자로 처리하고 정확한 이름은 이중따옴표로 입력합니다. 컬럼은 입력한 철자를 이중따옴표로 인용합니다. 문자열·한글·작은따옴표·줄바꿈·NULL·NUMBER·DATE·TIMESTAMP·시간대 TIMESTAMP·RAW를 지원하고 날짜는 NLS 의존을 줄인 변환식으로 만듭니다. Oracle 10g의 문자열 4,000바이트·RAW 2,000바이트 한계나 미지원 CLOB/BLOB·객체 타입은 오류를 표시합니다. **파일 생성만 수행하며 실행·COMMIT 문을 추가하지 않습니다.**

파일은 같은 폴더의 임시 파일에 작성한 뒤 성공하면 교체합니다. 새 파일은 소유자 읽기·쓰기, 기존 파일은 권한 비트를 유지합니다. 부모 디렉터리는 있어야 하며 심볼릭 링크는 지원하지 않습니다. 저장 중 외부 변경을 발견하면 재시도·덮어쓰기 검토를 요구합니다. SQL 저장과 같은 `.lazyora.lock`을 사용하므로 비정상 종료 후 잠금 해제 절차는 SQL 파일 안내를 참고하세요.

## 위험 SQL 실행 확인

메인 편집기에서 DDL과 **최상위 WHERE가 없는 UPDATE·DELETE**를 실행하면 사유와 실제 실행 대상 SQL을 먼저 보여줍니다. 선택한 SQL이 있으면 그 선택 부분만 확인합니다. 기본 선택은 **취소**이며 Enter 또는 Esc로 취소합니다. 실행 버튼을 방향키·Tab으로 선택한 뒤 Enter를 누르거나 마우스로 클릭해야 제출합니다. 취소하면 SQL·조회 결과·트랜잭션·실행 이력을 바꾸지 않습니다.

Tab으로 SQL 미리보기와 버튼을 순환하고 방향키·PgUp/PgDn으로 SQL을 읽습니다. F1 도움말을 닫으면 확인 화면으로 돌아옵니다. 확인창에 표시한 SQL을 그대로 제출하며 나중에 편집기 값이 바뀌더라도 다른 SQL을 실행하지 않습니다. 소스 적용·컴파일은 기존 DDL 확인창을 사용합니다.

주석·문자열·따옴표 식별자·서브쿼리 안의 WHERE는 바깥 UPDATE·DELETE의 조건으로 보지 않습니다. 조건을 확실히 검사하지 못한 UPDATE·DELETE도 확인합니다. DDL·관리 명령은 CREATE·ALTER·DROP·TRUNCATE·RENAME·COMMENT·GRANT·REVOKE·PURGE·FLASHBACK·ANALYZE·AUDIT·NOAUDIT·ASSOCIATE·DISASSOCIATE·UNDROP을 대상으로 합니다.

이 검사는 영향 행 수나 조건의 선택도를 판단하지 않습니다. **WHERE 1=1처럼 조건이 있어도 전체 행이 바뀔 수 있으며**, PL/SQL·동적 SQL·프로시저 내부 SQL·MERGE는 분석하지 않습니다. 경고가 없다는 뜻이 안전하다는 뜻은 아닙니다. Oracle DDL의 암시적 커밋과 ALTER SESSION/SYSTEM 등 관리 명령의 실제 동작은 명령에 따라 다릅니다. [Oracle SQL 분류 안내](https://docs.oracle.com/cd/B13789_01/server.101/b10759/statements_1001.htm)를 참고하세요.

## 조작

상단 메뉴는 파일·편집·세션·실행·보기·도구·도움말입니다. Alt+F/E/S/X/V/T/H로 각각 열고, 좌우로 메뉴 전환, 위아래로 선택, Enter로 실행, Esc로 닫습니다. 마우스로도 사용할 수 있습니다. 현재 사용할 수 없는 항목은 흐리게 표시하고 실행하지 않습니다. 메인 단축키·메뉴·F1 기본 명령 목록은 공통 정의를 사용합니다.

기능키는 [Toad 공식 단축키 안내(pp. 24–26)](https://i.dell.com/sites/csdocuments/shared-content_data-sheets_documents/en/guidetousingtoadfororacle.pdf)를 기준으로 배정합니다. **F2 쿼리 전체화면**, **Shift+F2 결과 전체화면**, **F6 쿼리/결과 전환**, **F7 SQL 전체 지우기**, **F8 SQL 이력**, **F10 문맥 메뉴**를 지원합니다. F7은 확인 후 지우며 실행 취소(Ctrl+Z)로 복원할 수 있습니다. 이력은 이번 앱 실행에서 제출한 SQL을 최대 100개까지 메모리에 보관하며 디스크에 저장하지 않습니다. 이력을 불러올 때 현재 SQL이 있으면 덮어쓰기를 확인하고, 자동으로 실행하지 않습니다.

**Ctrl+F 찾기**, **F3 다음 찾기**, **Shift+F3 이전 찾기**, **Ctrl+R 바꾸기**는 쿼리 편집기의 일반 문자열을 대소문자를 구분하여 찾습니다. 끝에 도달하면 순환합니다. F4는 선택한 객체 또는 커서 아래 객체의 상세를 열고, Ctrl+D는 객체명을 입력하는 상세 조회 창을 엽니다. F9·Ctrl+Enter·Shift+F9로 선택한 SQL을 실행하며, 선택이 없으면 커서 위치의 SQL 문장 또는 PL/SQL 단위를 실행합니다. 일반 SQL은 세미콜론, PL/SQL은 별도 줄 `/`로 구분하고 마지막 PL/SQL 단위는 `/`를 생략할 수 있습니다. 주석·문자열·따옴표 식별자·q/nq 인용 안의 구분자는 무시합니다. 문장 사이 공백에서는 다음 문장, 마지막 문장 뒤에서는 마지막 문장을 선택합니다. 따옴표·주석·괄호가 닫히지 않은 입력은 제출하지 않습니다. **F5**는 선택 영역 또는 전체 편집기를 스크립트로 실행합니다. **Ctrl+F9 구문 검사·F11 디버거 계속 실행**은 미지원 상태로 예약하며 DB 명령을 실행하지 않습니다.

전체화면에서 같은 키를 다시 누르면 분할 화면으로 돌아오고, 다른 창의 전체화면 키나 F6으로 표시할 창을 바꿉니다. **보기 → 창 최대화 / 복원**은 메뉴·상태·푸터를 유지하는 기존 최대화 기능입니다. 전체화면에서 F1 도움말이나 Alt+M 메뉴를 열면 임시로 일반 화면을 표시하고, 닫으면 전체화면으로 돌아갑니다. 스키마 표시·숨김은 Alt+B 또는 보기 메뉴를 사용합니다. 접속은 Alt+L 또는 세션 메뉴, 설정은 도구 메뉴에서 엽니다. Alt+C/Alt+R 커밋·롤백, Alt+Enter 실행, Ctrl+Q 종료는 LazyOra의 터미널용 추가 배정입니다.

결과는 **Ctrl+C 셀/범위 복사**, **Alt+Y 행 복사**, **Shift+방향키·마우스 드래그 범위 선택**을 지원합니다. 원본 값을 TSV로 클립보드에 전송 요청하며 미지원 터미널에서는 **편집 → 복사 내용 보기**로 터미널 기본 선택·복사를 사용합니다. 자세한 동작과 제한은 [터미널·복사 안내](terminal.md)를 참고하세요.

화면 최하단의 단축키 안내는 현재 포커스에 따라 바뀝니다. SQL 편집기에서는 `F9 / Ctrl+Enter` 실행과 전체화면 전환을, 결과 표에서는 셀·범위·행 복사와 이동을 표시합니다. 키보드나 마우스로 포커스를 바꾸면 즉시 갱신되며, 접속·설정·도움말에서는 해당 화면의 저장·닫기·스크롤 동작을 안내합니다. 하단 버튼을 클릭해도 해당 단축키와 같은 동작을 실행합니다. 버튼에 포커스가 있으면 **좌우 방향키**로 같은 줄의 버튼을 순환하고 **Enter**로 실행합니다. 폼과 상세화면의 버튼은 Tab/Shift+Tab으로 접근하며, 선택된 버튼은 **진한 파랑 배경·흰색 굵은 밑줄 글자**로 구분합니다(8/16색 포함). F1 도움말은 **목차와 선택한 주제의 본문**으로 나누어 현재 화면의 조작부터 보여줍니다. **0~9**로 현재 화면·SQL·결과·화면/메뉴·접속/설정·스키마/소스·트랜잭션·터미널/지원 범위·앱 정보·편집기 키맵을 선택합니다. 목차를 클릭하거나 Tab/Shift+Tab으로 목차에 이동해 방향키로 주제를 고르고 Enter로 본문에 이동할 수 있습니다. 본문은 방향키·PgUp/PgDn·마우스 휠로 스크롤합니다. 좁은 터미널에서는 목차를 위쪽에 배치하며, F1 또는 Esc로 닫으면 이전 화면과 포커스로 돌아갑니다.

메인 화면의 **Alt+C 커밋·Alt+R 롤백** 버튼은 SQL 편집기·결과 표의 포커스에 관계없이 항상 표시하며 마우스로도 실행할 수 있습니다.

기본 색상은 [Nord 팔레트](https://www.nordtheme.com/docs/colors-and-palettes/)를 참고했습니다. SQL·폼 입력칸은 흰색 계열 바탕과 어두운 글자, 버튼은 청회색, 선택·포커스는 청록색으로 구분합니다. 하단 단축키 영역은 별도 청회색 배경으로 표시합니다.

8색·16색 터미널에서만 입력창 테두리를 파랑, 결과·대화창 테두리를 청록으로 구분하며 포커스가 있는 창의 선을 굵게 표시합니다. 256색·True Color에서는 기존 테마를 유지합니다. SecureCRT에서 RGB 색상 명령을 처리하지 못하면 `TCELL_TRUECOLOR=disable ./lazyora-linux-amd64`로 터미널의 기본 팔레트를 사용해 시험할 수 있습니다.

Ctrl+Enter는 터미널이 Ctrl 조합을 구분해 전달할 때 동작합니다. 일반 Enter와 같은 입력으로 전달되는 환경에서는 Alt+Enter 또는 F9를 사용합니다. SecureCRT 매핑 방법은 [터미널 안내](terminal.md)를 참고하세요. 도움말은 접속 화면에서도 열 수 있으며 F1 또는 Esc로 닫으면 이전 화면과 입력 위치로 돌아갑니다.

정상 종료를 요청하면 항상 확인 팝업을 표시합니다. 변경 가능한 SQL을 실행한 후 앱에서 커밋·롤백하지 않은 내역이 있으면 **커밋 후 종료 / 롤백 후 종료 / 계속 사용**을 선택합니다. 변경 내역이 없어도 **종료 / 계속 사용**을 확인합니다. 기본 선택과 Esc는 계속 사용이며 기존 화면·SQL·조회 결과를 유지합니다. 실행 중이면 취소를 요청한 뒤 작업이 끝나면 종료를 확인합니다. 커밋·롤백 처리 실패 시 종료하지 않고 재접속하여 DB 처리 결과를 확인하도록 안내합니다.

종료창은 추적 중인 실행 건수와 최근 SQL을 보여줍니다. **내역 보기(Alt+V)** 또는 **세션 → 미커밋 내역 보기**에서 실행 시각·SQL·처리 행 수·성공/오류를 확인합니다. 목록에서 선택하면 원문 SQL을 보여주며 Tab으로 SQL 영역에 이동해 스크롤하고 Ctrl+C로 상세를 복사할 수 있습니다. Esc로 종료창에 돌아가도 커밋·롤백하지 않으며 기본 선택은 계속 사용입니다.

기록은 마지막으로 성공한 앱 커밋·롤백 이후 변경 가능 SQL과 소스 적용·컴파일을 대상으로 합니다. SELECT·메타데이터 조회는 제외하고 실행 실패·취소도 결과 확인이 필요할 수 있어 기록합니다. 커밋·롤백 성공 또는 새 접속 시 비우며 실패 시 보존합니다. 최근 100개를 메모리에만 보관하고 이전 생략 건수를 표시합니다. SQL 하나는 앞부분 64 KiB까지만 보관하며 잘림을 표시합니다. **행별 변경 전·후 비교나 실제 DB 미커밋 목록은 아닙니다.**

미커밋 안내는 앱의 실행 내역을 보수적으로 추적합니다. 단순 SELECT·스키마 탐색은 변경으로 표시하지 않으며, DDL·PL/SQL 내부 커밋이나 변경 가능 SQL의 실행 오류 이후에는 실제 DB 트랜잭션과 차이가 있을 수 있습니다. 강제 종료·접속 단절에는 확인 팝업을 보장하지 않습니다.

SELECT와 WITH 조회는 결과 표로 표시합니다. 결과는 최대 1,000행까지 가져옵니다. DML은 수동 커밋 방식입니다. **Oracle DDL은 암시적 COMMIT을 발생시킬 수 있습니다.** PL/SQL 프로시저 내부 COMMIT도 Oracle의 동작을 따릅니다. 재연결에 성공하면 이전 연결을 롤백하고 닫습니다. 일반 실행은 백그라운드 작업으로 처리하며 60초 제한과 취소 요청을 적용합니다. DB 전체 결과 내보내기는 60초 제한 없이 별도로 처리하고 Esc 취소를 제공합니다. 드라이버·네트워크 상태에 따른 취소 동작은 실DB 검증이 필요합니다.

F9는 한 번에 SQL 한 문장 또는 PL/SQL 단위 하나를 실행합니다. 여러 PL/SQL 단위를 나란히 작성할 때는 반드시 각 단위 뒤에 별도 줄 `/`를 넣으세요. 일반 SQL 끝의 세미콜론은 제거하고 PL/SQL 내부 세미콜론은 유지합니다. PL/SQL 끝의 별도 줄 `/`는 제거합니다. 메인 SQL 편집기의 일반 바인드 입력은 IN 전용이며 SQL*Plus 명령은 지원하지 않습니다. 루틴의 OUT·IN OUT·REF CURSOR는 아래 전용 실행 화면을 사용하세요. DBMS_OUTPUT은 Alt+P에서 켜고 F9/F5 또는 루틴 실행 후 수집합니다. PL/SQL 객체의 생성·수정은 스키마 탐색기의 소스 편집·컴파일 화면을 사용합니다. 현재 LOB 표시와 대형 단일 셀 메모리 사용량도 추가 검증이 필요합니다.


### 프로시저·함수 실행

스키마 브라우저에서 FUNCTION·PROCEDURE·PACKAGE를 선택하고 **실행 → 프로시저·함수 실행**을 엽니다. 객체 상세·인자 화면에서는 **실행(Alt+E)** 버튼을 사용합니다. SQL 편집기의 객체명에 커서를 놓고 실행 메뉴로 열 수도 있습니다. 패키지는 공개 멤버와 오버로드별 인자 목록 중 실행할 항목을 Enter로 선택합니다.

입력 화면은 IN·IN OUT 인자의 값·NULL을 구분하고, 확인된 IN 기본값은 ‘기본값 사용’을 제공합니다. **F9 → 확인**으로 실행하며 기본 선택은 취소입니다. 문자열·NUMBER(최대 38자리)·DATE(`YYYY-MM-DD`)·TIMESTAMP(`YYYY-MM-DD HH:MM:SS[.소수초]`, 최대 9자리, 대상 루틴·저장 컬럼의 정밀도 제한은 적용)·BOOLEAN(`true/false`)·RAW(16진수, 입력 최대 16,383바이트)를 지원합니다. NUMBER는 소수 정밀도를 보존하고 출력 날짜·숫자는 고정 형식으로 표시합니다. 값은 SQL에 삽입하거나 파일·실행 이력에 저장하지 않으며 폼을 닫으면 버립니다.

결과 목록에서 OUT·IN OUT·함수 반환값 또는 REF CURSOR를 선택하면 기존 결과 표로 표시합니다. Ctrl+C 선택 복사·Alt+Y 행 복사·Alt+W 내보내기가 가능하며 Esc로 결과 목록에 돌아옵니다. 다른 출력은 **보기 → 루틴 실행 결과**로 다시 선택합니다. 소스 편집 중 열어도 적용하지 않은 소스와 포커스를 보존합니다. 재접속하면 이전 루틴 결과를 제거합니다.

REF CURSOR는 최대 4개, 커서당 최대 1,000행을 가져오고 잘림을 표시합니다. NULL 커서는 빈 결과와 구분하며 IN·IN OUT 커서는 최초 NULL 입력만 지원합니다. 내보내기는 가져온 행만 대상으로 하며 루틴을 재실행하지 않습니다. 레코드·컬렉션·LOB·시간대 포함 타입은 아직 전용 실행 입력에서 지원하지 않습니다. 패키지의 강한 타입 커서와 NULL 커서도 SYS_REFCURSOR로 받아 Oracle이 반환 행의 호환성을 검사하도록 합니다.

구버전 Oracle 사전에 기본값 정보가 없으면 직접 입력합니다. 오버로드에서 기본값을 생략하면 다른 인자 조합을 선택할 수 있어 명시적인 값·NULL을 요구합니다. 선택한 조합의 메타데이터 타입으로 PL/SQL 지역 변수를 선언하며, Oracle이 모호한 조합으로 판단하면 오류를 표시합니다. 인자는 반환값을 포함해 최대 32개입니다.

루틴은 현재 세션의 수동 트랜잭션에서 실행하며 LazyOra가 자동 커밋·롤백하지 않습니다. 다만 루틴 본문 자체의 COMMIT·ROLLBACK·DDL은 Oracle 동작을 따릅니다. 성공·오류 후 모두 미커밋 가능 작업을 추적하고 DBMS_OUTPUT을 켰다면 출력도 별도로 수집합니다. 일반 실행과 같은 60초 제한·Esc 취소를 적용하며 드라이버·네트워크에 따라 취소 응답이 지연될 수 있습니다.


### 객체·컬럼 자동완성

SQL 편집기 또는 소스 편집기에서 **Ctrl+T**를 누릅니다. 메인 화면에서는 **편집 → 객체·컬럼 자동완성**과 문맥 메뉴로도 엽니다. Toad의 Code Insight 호출 키에 맞췄으며 Ctrl+Space 코드 템플릿과는 별개입니다. 자동으로 SQL을 실행하지 않고, **Enter로 선택한 항목만 현재 단어에 입력**합니다. Esc는 원문을 유지하고 닫으며 Ctrl+Z로 입력을 되돌릴 수 있습니다. 문자열·주석·바인드 이름 내부와 텍스트 선택 중에는 호출하지 않습니다.

`SELECT s.ti FROM sample_rows s`에서 `ti` 뒤에 커서를 놓으면 별칭 `s`의 `TITLE` 컬럼을 제안합니다. `FROM sam`은 현재 DB 스키마의 객체, `FROM other_schema.ta`는 해당 스키마의 객체, `schema.table.co`는 지정 객체의 컬럼을 조회합니다. FROM·JOIN의 테이블·뷰와 별칭을 읽고 중첩 SELECT·UNION 분기의 별칭은 섞지 않습니다. 일반 위치에서는 SQL/PLSQL 키워드·함수·타입도 제안합니다. 접속하지 않아도 키워드 완성은 가능합니다.

후보 화면에서 글자를 입력해 필터하고 방향키로 선택합니다. Tab은 필터·목록·버튼을 순환합니다. 필터의 **Ctrl+R / 새로고침**은 입력한 접두어로 DB 메타데이터를 다시 조회합니다. 목록은 최대 200개이므로 잘림이 표시되거나 원하는 이름이 없으면 접두어를 더 입력하고 Ctrl+R을 누르세요. 메타데이터는 세션별로 최대 48개 조회를 5분 보관하며 새로고침·재접속으로 비웁니다. 객체 조회는 접두어별 최대 2,000개, 테이블 컬럼은 최대 4,096개, 한 문장의 FROM/JOIN 객체는 최대 8개로 제한합니다.

이름은 DB의 실제 대소문자를 보존해 큰따옴표로 입력하며, 공백·한글·점·따옴표가 포함된 식별자도 지원합니다. 인용 접두어는 대소문자를 구분하고 일반 접두어는 구분하지 않습니다. 현재 스키마는 접속 계정이나 브라우저에서 선택한 계정으로 추정하지 않고 `CURRENT_SCHEMA`를 읽으므로 ALTER SESSION도 반영합니다. 메타데이터 조회는 현재 세션의 미커밋 작업을 유지하며 별도 커밋·롤백하지 않습니다.

CTE·파생 테이블의 SELECT 결과 컬럼은 아직 추론하지 않고, 같은 이름의 실제 테이블로 잘못 조회하지 않도록 구분합니다. 시노님 대상·DB 링크·패키지 멤버와 PL/SQL 지역 변수의 심볼 해석은 지원하지 않습니다. 일부 메타데이터를 읽지 못하면 제한 안내와 나머지 후보를 표시합니다. 소스 전체를 검증하는 SQL 파서는 아니므로 복잡한 문맥은 실제 객체명을 확인하세요.

단축키 참고: [Quest Code Insight 안내](https://support.quest.com/toad-for-oracle/kb/4272782/display-pick-list-toad-insight-is-not-working-it-does-not-display-after-typing-a-period).


### SQL·PL/SQL 정렬

**Ctrl+Shift+F** 또는 **편집 → SQL·PLSQL 정렬**을 사용합니다. 선택한 코드가 있으면 그 범위만, 없으면 현재 SQL 탭 전체를 정렬합니다. 소스 편집기에서도 같은 키를 사용하거나 아래 정렬 버튼을 누릅니다. 구형 터미널이 Ctrl+Shift+F를 Ctrl+F와 구분하지 못하면 메뉴·버튼을 사용하세요. 일반 Ctrl+F 찾기 동작은 그대로입니다.

SQL 절·선택 컬럼·블록을 줄바꿈하고 두 칸 들여쓰기로 정리합니다. 키워드 대소문자는 바꾸지 않으며 문자열·q/nq 인용·인용 식별자·주석·숫자·바인드·복합 연산자의 내용을 보존합니다. SQL 파서·구문 검사 기능은 아니며 모든 Oracle 구문의 모양을 완전히 정렬하는 기능은 아닙니다. 토큰이 달라지면 결과를 적용하지 않습니다. 미완성 인용·주석이나 토큰 중간을 자른 선택 영역도 거부합니다.

선택 밖 코드와 기존 외부 공백·기준 들여쓰기를 유지합니다. 전체 정렬은 원래 토큰의 커서 위치를 따라가며, 선택 정렬은 정렬한 범위를 선택 상태로 유지합니다. **Ctrl+Z 한 번으로 되돌릴 수 있습니다.** 소스 정렬은 편집 내용만 바꾸고 DB에 적용·컴파일하지 않습니다. SQL 실행·저장도 자동으로 하지 않습니다.

선택 범위는 최대 4 MiB, 출력은 최대 16 MiB, 들여쓰기 중첩은 최대 64단계입니다. 큰 파일은 필요한 범위를 선택해 정렬할 수 있습니다. 표준 Go 코드로 구현하며 별도 외부 포맷터 설치나 라이선스는 추가하지 않습니다.

단축키 참고: [Quest Format Code 안내](https://support.quest.com/de-de/technical-documents/toad-for-oracle/2026%20r1/getting-started-guide/33).

## 편집기 키맵

도구 → 설정 → **편집기 키맵(Alt+K)**에서 **기본 / Vim / Notepad++**를 선택하고 저장합니다. 기존 설정 파일에는 기본 키맵을 적용하며, 변경해도 SQL 원문·탭·선택·실행 취소 기록을 지우지 않습니다. 설정 파일의 `editor_keymap`은 생략/빈 문자열이면 기본, `vim` 또는 `notepad++`입니다.

키맵은 포커스가 있는 SQL·소스 편집기에만 적용합니다. 접속 입력·메뉴·결과 그리드의 조작은 유지하며 F9 실행, F5 스크립트, 세션의 커밋·롤백과 Ctrl+Q 종료 확인은 기존 경로를 사용합니다. Tab은 기존처럼 패널·버튼 이동입니다. 소스에서는 F9 컴파일 확인, **Alt+R 다시 조회 / Alt+X 닫기 / F10 편집 메뉴**를 사용합니다. 터미널 붙여넣기는 모드와 관계없이 원문을 삽입합니다.

| 키맵 | 지원하는 조작 |
| --- | --- |
| 기본 | 기존 단축키 유지. Ctrl+L 전체 선택, Ctrl+D 빠른 객체 상세, Ctrl+T 자동완성, Ctrl+R 바꾸기(소스는 다시 조회) |
| Vim | NORMAL·INSERT·VISUAL 표시. hjkl/방향키, w/b/e, 0/^/$, gg/G, 이동·d/y/c·x/X의 최대 999회 횟수. i/a/I/A/o/O 입력, Esc 일반 모드, v/V 선택. d/y/c와 이동 또는 dd/yy/cc, x/X/D/C, p/P, u 및 Ctrl+R 다시 실행. /·? 일반 문자열 찾기, n/N 같은/반대 방향 반복 |
| Notepad++ | Ctrl+A 전체 선택, Ctrl+D 선택/줄 복제, Ctrl+L 줄 잘라내기, Ctrl+Shift+L 줄 삭제, Ctrl+Shift+위/아래 줄 이동, Ctrl+T 위 줄과 바꾸기. 선택 없는 Ctrl+C/X는 줄 복사/잘라내기. Ctrl+Space 자동완성, Ctrl+F·F3 찾기, Ctrl+R 바꾸기 |

Vim은 위에 명시한 일부 명령을 지원합니다. 전체 Vim·Ex(`:`)·텍스트 객체·블록 선택·여러 레지스터·매크로·점 반복은 지원하지 않습니다. 삽입 실행 취소 묶음은 기존 편집기를 따릅니다. Vim의 Ctrl+R은 바꾸기/소스 다시 조회 대신 다시 실행이므로 편집 메뉴 또는 소스의 다시 조회 버튼을 사용하세요. 새로 선택한 편집기/다른 탭은 NORMAL에서 시작합니다.

Notepad++에서는 Ctrl+D/Ctrl+L/Ctrl+T를 편집 조작으로 사용하므로 전체 선택은 Ctrl+A, 자동완성은 Ctrl+Space, 객체 상세는 F4/보기 메뉴를 사용합니다. Ctrl+H는 구형 터미널의 Backspace와 구분되지 않아 바꾸기에 배정하지 않습니다. Ctrl+Space·Ctrl+Shift 조합을 전달하지 못하는 터미널은 편집 메뉴(SQL: Alt+E, 소스: F10)를 사용하세요. F1 도움말과 포커스별 하단 안내도 선택한 키맵을 반영합니다.

## 객체 DDL·제약조건·인덱스

스키마 객체의 상세 화면에서 **Alt+D DDL / Alt+C 제약조건 / Alt+I 인덱스**를 엽니다. 창 안에서는 **1/2/3**으로 전환하고, Tab으로 목록·상세·버튼을 이동합니다. 필요한 항목만 조회하며 Ctrl+R로 현재 항목을 새로 고칩니다. 창을 닫으면 캐시를 버립니다. 목록의 Ctrl+C는 선택 행의 원문 TSV, 상세의 Ctrl+C는 검사 조건·인덱스 식 등 상세 원문, DDL의 Ctrl+C는 조회한 DDL 전체를 복사합니다. Esc는 조회 중 취소, 대기 중 뒤로 가기입니다.

DDL은 DBMS_METADATA로 읽으며 테이블·뷰·구체화 뷰·프로그램·시퀀스·동의어·인덱스·트리거·타입을 지원합니다. 패키지/타입의 명세와 본문을 구분하고, 생성·컴파일·커밋·롤백하지 않습니다. 일반 사용자는 자기 객체 외의 DDL을 읽지 못할 수 있습니다. 이 경우 실제 Oracle 오류를 표시하며 임의의 대체 DDL을 만들지 않습니다. 제약조건·인덱스는 별도 ALL_* 조회이므로 DDL 권한 오류와 독립적으로 열 수 있습니다.

제약조건에는 종류(C/P/U/R 등), 상태·검증 상태, 순서가 있는 컬럼·복합 외래키 참조 컬럼, 삭제 규칙·지연 정보·검사 조건을 표시합니다. 인덱스에는 소유자·종류·고유성·상태, 컬럼 순서·ASC/DESC·함수 식을 표시합니다. 권한에 따라 참조 테이블의 상세가 보이지 않을 수 있으며, 기본 참조 소유자·제약조건 이름은 유지합니다.

미리보기는 DDL 최대 262,144자(초과 시 오류), 항목별 제약조건/인덱스 256개·컬럼 2,048개로 제한합니다. 목록 제한과 조회 실패·부분 정보는 화면에 표시합니다. 구형 Oracle의 LONG 및 임시 CLOB 드라이버 제한을 피하려고 서버에서 문자열로 변환해 전달하고 임시 LOB를 해제합니다. 실제 10g/19c 검증 여부는 호환성 검증 기록과 별개입니다. 권한 모델과 객체 종류는 [Oracle DBMS_METADATA 설명서](https://docs.oracle.com/cd/B19306_01/appdev.102/b14258/d_metada.htm)를 참고하세요.
