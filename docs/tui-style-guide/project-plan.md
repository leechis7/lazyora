# 독립 TUI 스타일 가이드 프로젝트 준비 계획

> 보관 설계 자료 / Archived design record. 작성 당시의 제안·이관 계획을 보존합니다. 현재는 Tuivory v0.0.1 패키지 도입을 완료했습니다. 현행 기준: [한국어](../ui-style.md) · [English](../en/ui-style.md). 아래 ‘예정/독립 전’ 표현은 당시 상태입니다. / Future-work wording below reflects the original date, not current implementation.

상태: 향후 프로젝트 설계 메모. 별도 저장소·패키지·사이트는 아직 만들지 않았습니다.

## 목표와 첫 산출물

목표는 터미널 앱 개발자가 테마·색상 능력·컴포넌트 상태를 일관되게 설계하고, 표시 결과를 비교할 수 있는 가이드를 제공하는 것입니다. 첫 공개 범위는 **가이드 + 기본 테마 예시 + 컴포넌트 견본 + 검증 기록**으로 제안합니다. 범용 위젯 프레임워크 제작은 후속 단계입니다.

| 범위 | 첫 단계에 포함 | 이후 검토 |
| --- | --- | --- |
| 가이드 | 의미별 토큰, 색상 프로필, 상태, 키보드, 셀 배치, 모달 | 분야별 패턴 확장 |
| 테마 | 다크·라이트·흑백 예시, ANSI8/16/256/RGB | 사용자가 제공하는 테마의 검증·배포 |
| 견본 | 입력·선택·버튼·목록·탭·메뉴·표·팝업 | 문법 강조·대형 데이터·복잡한 편집기 |
| 구현 연결 | Go/tcell/tview 예제 하나 | Lip Gloss·Textual·Ratatui 어댑터 |
| 도구 | 팔레트 대비·위젯 캡처·단말 관찰 구분 | 공통 스키마·범용 CLI·웹 탐색기 |

Oracle 접속, 암호 보관, SQL 실행, ROWID 편집, Toad 단축키는 LazyOra에 둡니다. 공개 견본은 DB 없이 합성 데이터만으로 실행할 수 있어야 합니다.

## 향후 저장소 구조안

아래는 설계안이며 아직 존재하는 파일을 뜻하지 않습니다. 프로젝트 이름과 패키지 경로는 출범 시 정합니다.

```text
README.md                  목적, 빠른 시작, 검증 범위, 한·영 요약
LICENSE                    출범 시 결정한 라이선스
CONTRIBUTING.md            원칙/사례/어댑터 기여 절차
CHANGELOG.md               규칙·토큰·어댑터 변경 이력
docs/
  principles/              공통 설계 원칙
  patterns/                컴포넌트와 상태 조합
  terminal-profiles/       색상·키·마우스·선 문자 제약
  sources.md               출처, 조사일, 도출한 규칙
  decisions/               결정 이유·예외·폐기한 대안
spec/                      향후 토큰/캡처/증거 형식과 예시
themes/                    검증 수준을 표시한 기본 테마 예시
examples/                  DB 없는 컴포넌트 견본
adapters/tcell/            범용 계약을 실제 위젯 스타일로 연결
tools/                     대비·캡처 분석·단말 견본
fixtures/                  합성 텍스트/그리드/상태 조합
evidence/                  단말 메타데이터, 결과, 알려진 한계
```

먼저 문서와 한 개 어댑터로 계약이 성립하는지 확인한 뒤 모듈·패키지 구조를 결정합니다. 특정 언어용 SDK나 CSS 엔진을 먼저 만들지 않습니다.

| [기존 스타일 코드](../../internal/ui/theme.go) | tcell/tview 연결 사례 | 현재 역할 혼합·테마 치환 문제를 해결한 뒤 검증된 패턴만 추출 |

재사용 전에는 파일별 작성자·원본 출처·의존 코드·고지 사항을 기록합니다. 현재 저장소의 라이선스는 [LICENSE](../../LICENSE)에서 확인합니다. 독립 프로젝트의 문서·코드·테마·이미지 라이선스는 사용자 결정 사항이며, 이 계획으로 기존 자료를 임의로 재라이선스하거나 외부 문서/라이브러리 코드를 복제하지 않습니다. 원문을 옮기기보다 출처 링크와 직접 작성한 설명을 유지합니다.

## 토큰과 어댑터 사이의 경계

향후 공통 토큰은 역할·전경/배경·속성을 보존해야 합니다. RGB 하나로 ANSI 색을 모두 변환해 저장하지 않습니다.

```text
토큰 문서
  형식 버전, 토큰 ID, 의미, 별칭, 테마/프로필별 값
  색 값: ANSI 인덱스 / 256색 인덱스 / RGB를 구분
  속성: bold, underline 등과 fallback 정책
  상태: focused / selected / disabled / changed / invalid
  검증: 계산 모델, 확인 범위, 실제 단말 증거

어댑터
  토큰 해석 → 프레임워크 스타일 적용
  포커스/선택/입력 상태는 앱이 전달
  앱 데이터와 작업 실행에는 접근하지 않음
```

DTCG의 역할/별칭 개념은 참고하되 ANSI 인덱스·터미널 속성은 일반 RGB 토큰과 같지 않습니다. 사용자 정의 확장 또는 별도 프로필 문서로 표현할지는 출범 시 결정합니다. 호환성을 검증하기 전 ‘DTCG 완전 호환’을 표방하지 않습니다. 지금 CSV는 이 스키마의 확정본이 아닙니다.

의존 방향은 `앱 → 어댑터 → 공통 토큰/규칙`입니다. 공통 코어가 앱 내부 모듈이나 DB 드라이버를 참조하면 추출 완료로 보지 않습니다. 단말 I/O의 소유권은 앱/프레임워크에 두고, 공통 스타일 해석 과정에서 stdin 조회나 터미널 설정 변경을 수행하지 않습니다.

## 검증 증거 양식

각 사례에는 아래 정보를 함께 남깁니다. 실제 단말을 확인하지 못한 항목은 빈칸 대신 ‘미확인’으로 표시합니다.

```text
규칙/컴포넌트 ID:
가이드·테마·어댑터 버전 또는 커밋:
앱/위젯 버전, OS/아키텍처:
테마, 색상 프로필, TERM/COLORTERM, 라이브러리가 보고한 색상 수:
단말 프로그램/버전, 로컬/SSH/tmux 등 연결 경로:
ANSI 팔레트(참조/사용자 변경/미확인), 굵게 처리 설정:
창 크기(열×행), 폰트, 언어:
전제 상태와 조작 순서:
기대 결과 / 관찰 결과:
검증 방식: 팔레트 계산 / 위젯 시뮬레이션 / 실제 단말
결과: 통과 / 실패 / 미확인, 예외와 근거:
캡처/로그 경로, 확인 날짜:
```

실제 호스트명·사용자명·암호·업무 SQL·결과값은 공개 fixture에 넣지 않습니다. 원칙의 신뢰도는 적용한 모든 단말의 범위를 명시해서 설명하고, 한 단말의 결과를 전체 환경으로 일반화하지 않습니다.

## 단계별 진행과 출범 조건

| 단계 | 할 일 | 완료 판단 |
| --- | --- | --- |
| 0. 준비 | 공통/앱별 자료 구분, 출처·추출 계획 정리 | 현재 문서 범위. 제품 구현 완료를 의미하지 않음 |
| 1. 적용 사례 | LazyOra에 공통 스타일 적용, 발견한 결함 수정 | 테마 왕복·상태 보존·실제 단말 검증 근거 확보 |
| 2. 독립 견본 | DB 없는 최소 앱으로 같은 컴포넌트 구현 | LazyOra 내부 모듈 없이 12조합과 상태를 재현 |
| 3. 계약 확정 | 토큰/증거 형식, 어댑터 책임, 호환 정책 정리 | 두 사용 사례에서 앱별 조건이 공통 코어로 새지 않음 |
| 4. 독립 출범 | 이름·저장소·라이선스·문서 언어·공개 범위 결정 | 사용자 승인 후 이관. 이후 별도 버전 정책 수립 |
| 5. 확장 | 다른 프레임워크 적용·기여 지침·공개 사이트 | 해당 어댑터의 실제 검증 결과와 함께 제공 |

출범 전에 결정할 사항: 프로젝트 이름, 가이드 중심인지 라이브러리도 배포할지, 문서/코드 라이선스, 한국어·영어 제공 범위, 첫 지원 단말과 프레임워크. 위 항목은 현재 미결정으로 남깁니다. 이 문서의 단계를 Jira 신규 일감으로 자동 등록하거나 별도 프로젝트로 생성하지 않습니다.

## 출처 관리와 변경 정책

공식 자료 링크와 LazyOra 적용 판단은 [조사표](../ui-style-proposal.md#1-조사-결과와-채택-방향)에 있습니다. 독립 프로젝트로 옮길 때 각 자료에 조사일(현재 2026-10-23), 관련 절, 도출한 규칙 ID와 재확인 일자를 붙입니다. 라이브러리 API 예제는 버전/커밋을 고정해 재확인합니다.

규칙 변경은 문제와 근거를 먼저 남깁니다. 토큰 ID 변경·삭제, 기본 키 동작 변화, 프로필 fallback 변화는 영향 범위를 기록하고 어댑터 예제를 함께 갱신합니다. 시각 개선 후보와 실제 검증 완료 값을 구분하며, 버전과 major 변경은 별도 프로젝트 운영 정책 및 사용자 결정에 따릅니다.
