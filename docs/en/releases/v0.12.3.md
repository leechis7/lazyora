LazyOra v0.12.3 is a patch release fixing cell editing, real-cursor behavior and dirty markers through Tuivory Go v0.11.1.

### Fixes

- Enter and double-click immediately edit the selected cell. Unavailable edits explain why without automatically opening details. Keep cell details in the context/View menu and the Alt+D dialog editor.
- Replace the local cell-input renderer with public Grid edit APIs. Cancelling change review restores the same draft/cursor. No UPDATE is queued before approval; result/tab replacement invalidates stale approvals.
- Tuivory owns actual cursor position/visibility, glyph widths and clipping. Preserve terminal cursor-shape/blink preferences through the public TTY filter, avoiding forced cursor controls and SecureCRT `q` leakage.
- Separate edited-cell backgrounds/`*` from aggregate dirty-row gutter `*`, without coloring unrelated cells. Commit/rollback clears these cues.
- Retain Ctrl+U clear, Alt+Delete NULL, Proceed as the review default, original-value copying, Oracle ROWID/original-column checks and manual transactions.

### Verification and scope

Local full tests, focused race, vet and Linux ARM64 build pass. Actual-app tests cover96 cursor combinations across language/theme/color/glyph/entry modes,24 dirty-marker combinations, pending/rejected review, NULL, Unicode, stale approval and focus restoration. Four ARM64 demo PTYs (unset/empty TERM, ansi, xterm) verify startup/confirmed exit and absence of forced cursor-command leakage. [Bilingual evidence](https://github.com/leechis7/lazyora/blob/v0.12.3/docs/audits/lora-76-tuivory0111.md).

GitHub CI/Release runs full race/vet and Linux/Windows/macOS AMD64/ARM64 builds. No live-DB UPDATE, CentOS or physical SecureCRT/Windows/macOS console blink test in this work. Newly available SDK pinning, range paste, Tab edit traversal and other workbench capabilities are not exposed as new product commands. The SQL editor backend replacement and broader LORA-76 scope remain.
