# 대용량 내보내기 측정 — 2026-10-20

LORA-34 전체 결과 내보내기, 미커밋 개발 브랜치의 공통 256 KiB 파일 출력 버퍼 적용 결과입니다. 아래는 한 번씩 실행한 관측값으로, 다른 DB·디스크·네트워크의 속도를 보장하지 않습니다.

## 측정 조건

- Linux ARM64, ARM Neoverse-N1 2 vCPU, Go 1.26.9. 프로젝트가 있는 ext4 파일시스템에 저장했습니다. `/tmp`의 메모리 파일시스템은 출력에 사용하지 않았습니다.
- `generated`는 DB 없이 행을 순차 생성하고, `oracle`은 같은 서버의 Docker Oracle Free에서 읽기 전용 SELECT를 실행합니다. 테스트 테이블을 만들거나 사용자 데이터를 변경하지 않습니다.
- NUMBER ID, 한글·작은따옴표·줄바꿈을 포함한 약 100바이트 문자열, 실제 NULL과 문자열 NULL을 번갈아 담는 3컬럼입니다. LOB나 초대형 셀은 포함하지 않습니다.
- 각 형식·행 수를 별도 프로세스에서 실행합니다. 시간은 조회 커서 열기(Oracle), 순차 읽기·인코딩·쓰기·버퍼 Flush·파일 Sync·대상 파일 교체를 포함합니다. 접속·컴파일·TUI 렌더링과 사후 파일 검사는 제외합니다. UI와 같은 250ms 진행 알림 제한 계산은 포함합니다.
- 파일 전체를 메모리에 읽지 않고 CSV·TSV 레코드, INSERT 문 수, XLSX 내부 XML 행 수를 사후 검사합니다. 모든 경우 요구 행 수와 일치했습니다.
- 최대 RSS는 사후 파일 검사 전에 읽은 Linux 프로세스 VmHWM입니다. Go 힙 최대는 5ms 간격의 관측값이며, 총 할당량은 실행 중 누적 할당이므로 동시 메모리 사용량과 다릅니다.
- 파일 캐시·다른 프로세스와 DB의 자원 경쟁·스토리지 계층의 영향을 받을 수 있습니다. 반복 평균이나 원격 DB/WAN 측정이 아닙니다.

## INSERT 버퍼 적용 전후

같은 generated 데이터·파일시스템으로 비교했습니다. 변경 전에는 각 INSERT마다 출력 Writer를 호출했고, 변경 후에는 공통 버퍼가 파일 쓰기를 모읍니다. 단일 실행 결과이므로 차이를 일반적인 향상률로 해석하지 않습니다.

| 행 수 | 적용 전(초) | 적용 후(초) |
| ---: | ---: | ---: |
| 100,000 | 0.377 | 0.276 |
| 1,000,000 | 3.940 | 2.984 |

100만 행에서도 프로세스 메모리는 수십 MiB 범위로 유지됐습니다. 행 수에 비례하여 전체 결과를 메모리에 누적하지 않습니다. 한 행의 크기·드라이버 fetch·압축 버퍼에 따른 메모리 사용은 별도로 존재합니다.

## 재현

Oracle Free가 실행 중이고 `.env`가 준비되어 있어야 합니다. 명령은 프로젝트 루트에서 실행합니다. Go는 PATH에 있어야 합니다.

```sh
make -C test/oracle export-bench

# 파일 저장만 측정
BENCH_SOURCES=generated make -C test/oracle export-bench

# Oracle 조회 포함 100만 행 CSV만 측정
BENCH_SOURCES=oracle BENCH_ROWS=1000000 BENCH_FORMATS=csv make -C test/oracle export-bench
```

`BENCH_SOURCES`, `BENCH_ROWS`, `BENCH_FORMATS`에는 공백으로 구분한 목록을 지정할 수 있습니다. `BENCH_DIR`로 출력할 파일시스템의 기존 디렉터리를 지정합니다. 기본값은 `test/oracle/`이며, 임시 실행파일과 측정 출력은 종료 시 제거합니다. 각 측정은 최대 10분, 테스트 프로세스는 15분 제한입니다. 비밀번호는 `.env`에서 읽고 로그에 출력하지 않습니다.
