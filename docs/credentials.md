# 암호 관리

DB 비밀번호는 기본적으로 저장하지 않습니다. 접속 화면에서 **비밀번호 저장 (암호화)**을 선택하고 **저장(Ctrl+S)**을 누른 경우에만 저장합니다. 접속 버튼은 저장 여부를 바꾸지 않습니다.

## 처음 저장하기

1. 접속 정보와 DB 비밀번호, 별칭을 입력합니다.
2. **비밀번호 저장 (암호화)**을 선택하고 저장합니다.
3. 처음에는 마스터 비밀번호를 두 번 입력합니다. 8글자 이상인 긴 암호문을 권장합니다.
4. 이후 저장된 접속을 선택하면 마스터 비밀번호로 잠금을 해제하고 DB 비밀번호를 불러옵니다. 이번 실행 중 잠금이 해제되어 있으면 다시 묻지 않습니다.

마스터 비밀번호 입력은 `Ctrl+Enter` 또는 진행 버튼으로 적용하고 `Esc`로 취소합니다. 마스터 암호를 잊어도 **Esc로 잠금 해제를 취소 → DB 비밀번호 직접 입력 → 접속(Ctrl+Enter / Alt+C)**할 수 있습니다. 접속만 할 때는 저장소 초기화나 다시 저장할 필요가 없습니다. 호스트·포트·계정·접속 방식·서비스 이름을 수정하면 자동으로 불러온 비밀번호는 비웁니다. 다른 접속으로 전송하지 않도록 다시 입력하세요.

## 잠금·변경·삭제

메인 또는 접속 화면의 **Alt+K**, 메인 메뉴의 **도구 → 암호 관리**에서 관리합니다. 버튼은 Tab·좌우 방향키로 이동하고 Enter 또는 마우스로 실행합니다.

- **잠금 해제**: 기존 마스터 비밀번호를 입력합니다. 저장소가 없으면 최초 설정합니다.
- **잠금**: 메모리 키와 접속 화면의 암호 입력값을 비웁니다. 현재 Oracle 세션은 끊지 않습니다.
- **마스터 변경**: 먼저 잠금을 해제한 후 새 마스터를 두 번 입력합니다. 저장된 DB 비밀번호들을 새 키와 salt로 다시 암호화합니다.
- **초기화**: 확인 후 저장된 DB 비밀번호를 모두 삭제합니다. 마스터 비밀번호 없이도 가능하며 접속 프로필과 현재 Oracle 세션은 유지합니다. 기본 선택과 Esc는 취소입니다.
- **접속별 저장 해제**: 접속 화면에서 암호화 저장을 해제하고 저장합니다. 해당 접속의 저장 암호를 삭제하며 다른 접속은 유지합니다. 삭제를 위해 잠금 해제가 필요할 수 있습니다.

**마스터 비밀번호는 복구할 수 없습니다.** 잊었다면 전체 초기화 후 DB 비밀번호를 다시 등록합니다. 저장 파일의 과거 백업까지 삭제되는 것은 아닙니다. 별칭을 바꾸어 저장하면 기존 동작처럼 별도 접속으로 추가됩니다.

## 저장 위치와 호환성

Linux 기본 경로는 다음과 같습니다. 다른 OS에서는 사용자 설정 폴더를 사용합니다.

| 파일 | 내용 |
| --- | --- |
| `~/.config/lazyora/connections.json` | 별칭·접속 정보·고유 ID·암호 저장 여부. 비밀번호 없음 |
| `~/.config/lazyora/credentials.enc` | 암호화한 DB 비밀번호와 salt·암호화 형식 정보 |

`LAZYORA_CONFIG`로 설정 경로를 바꾸면 같은 폴더에 저장합니다. 설정·접속 파일과 이름이 충돌하면 암호 저장소 이름 앞에 `secret-`을 붙입니다. 비밀번호 미저장 상태에서는 암호 저장소를 만들지 않습니다. 기존 프로필은 계속 읽을 수 있고 저장할 때 고유 ID를 추가합니다.

저장소는 **OS 사용자별**입니다. 서로 다른 OS 계정은 각자의 설정 경로를 사용하지만, **같은 OS 계정이나 설정 경로를 공유하면 저장소도 공유**합니다. 마스터 비밀번호와 암호화 파일을 함께 평문 보관하거나 공유하지 마세요.

## 암호화와 오류 처리

- Argon2id로 키를 유도합니다: salt 16바이트, 메모리 64 MiB, 3회, 병렬도 2, 출력 32바이트. 마스터 비밀번호와 별도 검증 해시는 저장하지 않습니다.
- AES-256-GCM으로 저장소 내용을 암호화·인증하며 Go의 `NewGCMWithRandomNonce`로 매번 새 nonce를 생성합니다. 접속 ID와 대상 정보도 암호문 안에 넣어 다른 대상의 암호로 오인하지 않도록 합니다.
- Linux/macOS 저장 파일은 `0600`, 새 폴더는 `0700`으로 만듭니다. Windows의 접근 제어는 사용자 설정 폴더의 ACL에 따릅니다. KDF 비용과 파일 크기를 제한하여 변조된 파일이 과도한 메모리를 요구하지 않도록 합니다.
- 마스터 비밀번호는 파일·로그·설정에 저장하지 않습니다. 잠금·종료 시 키 바이트와 입력값을 지우지만, Go 런타임·OS의 메모리 복사본까지 완전히 지운다고 보장하지 않습니다. 서버 관리자나 이미 잠금 해제된 프로세스 접근까지 방어하는 기능은 아닙니다.
- 잘못된 마스터·파일 변조는 복호화를 거부하고 기존 암호 파일을 보존합니다. 암호 저장소를 읽지 못해도 암호화 저장을 끄고 직접 비밀번호를 입력하는 기존 접속은 가능합니다.
- 임시 파일에 쓰고 동기화한 뒤 교체합니다. 동시 쓰기는 잠금 파일과 기존 파일 비교로 거부하며, 변경 충돌 시 **잠금 → 다시 잠금 해제**한 후 재시도합니다. 비정상 종료로 `credentials.enc.lock`이 남으면 모든 LazyOra 실행을 종료한 뒤 해당 잠금 파일만 제거합니다.
- 접속 JSON과 암호화 저장소는 별도 파일입니다. 암호 저장 실패 시 공개 접속 정보 복원을 시도하며, 복원이나 최종 표시 갱신도 실패하면 오류를 표시합니다. 오류가 난 상태를 저장 성공으로 간주하지 말고 파일 접근 권한·저장 공간을 확인한 후 다시 저장하세요.

같은 설정 폴더를 쓰는 인스턴스의 접속 저장·저장 해제·전체 암호 초기화는 프로필의 `.lock` 파일을 먼저 확보하고, 암호화 저장소 갱신과 실패 복구가 끝날 때까지 유지합니다. 다른 인스턴스가 저장 중이면 잠시 후 재시도하세요. 접속 창을 연 뒤 목록이 바뀌었다면 저장을 거부하고 입력을 유지합니다. 창을 다시 열어 최신 목록을 확인한 뒤 편집을 적용하세요. 암호화 저장소의 충돌 메시지는 별도로 잠금·잠금 해제가 필요할 수 있습니다.

두 파일을 하나의 파일시스템 트랜잭션으로 교체하는 것은 아니므로 강제 종료·디스크 오류 중의 완전한 복구는 보장하지 않습니다. 비정상 종료로 `connections.json.lock`(사용자 지정 경로는 해당 프로필 파일명 뒤 `.lock`)이 남으면 같은 설정 폴더를 사용하는 모든 LazyOra를 종료한 뒤 잠금 파일만 제거하세요. 이 보호는 같은 잠금 규칙을 사용하는 버전끼리 적용되며 외부 편집기나 구버전의 직접 쓰기를 막지는 않습니다.

구현 근거: [Go Argon2id](https://pkg.go.dev/golang.org/x/crypto/argon2), [Go AES-GCM](https://pkg.go.dev/crypto/cipher#NewGCMWithRandomNonce).
