LazyOra v0.16.0 adds **Session → Session browser** for Oracle sessions and lock blocking relationships.

- Reading sessions requires access to `GV$SESSION`. Blockers and waiters appear first, with up to 500 entries.
- **Terminate blocker** requires `ALTER SYSTEM` and verifiable account protection metadata. The confirmation defaults to **Cancel**. LazyOra rechecks the target and blocking relationship before execution and protects the current session, background sessions, and Oracle-maintained accounts. Older databases without account protection metadata are read-only.
- Oracle rolls back the target's uncommitted work. The SQL editor's transaction stays separate.

Oracle Free tests covered actual row locks, waiter resumption, target rollback, and isolation from the SQL editor's transaction. The session browser was not tested against live RAC or older Oracle deployments.

AMD64 and ARM64 executables are available for Linux, Windows, and macOS. Verify them against `SHA256SUMS`. On Linux and macOS, grant execute permission with `chmod +x <executable>`.
