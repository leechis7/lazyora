[최초 조사](lora-69.md)와 [설계 제안](../ui-style-proposal.md)을 바탕으로 LazyOra의 공통 스타일을 적용했습니다. 동작 기준은 [UI 스타일 규칙](../ui-style.md), 독립 프로젝트 준비 자료는 [가이드 색인](../tui-style-guide/README.md)에 있습니다.

## 적용 내용

- 테마와 출력 능력을 분리해 8색·16색·256색·True Color를 해석합니다. 공통 토큰은 `internal/ui/style_tokens.go`에 두고, 8색에는 밝은색 인덱스를 사용하지 않습니다.
- 폼 설명은 입력 필드의 검정 글자색을 상속하지 않습니다. 읽기 전용 설명, 입력, 선택, 비활성 버튼에 각각 읽을 수 있는 스타일을 적용합니다.
- 배경 역할을 기록해 제목도 실제 배경에 맞춰 표시합니다. 흑백 복사창의 흰 바탕/흰 제목 문제를 해결했습니다.
- ANSI 선택·입력·미커밋 셀에는 검정 전경이 회색으로 바뀌는 Bold 조합을 적용하지 않습니다. SQL 문법색도 프로필별로 정하고 제한 색상에서는 필수 정보의 대비를 우선합니다.
- 객체·소스 진단·인자·미커밋 작업·스크립트 결과 같은 상세 표는 첫 그리기부터 공통 헤더/본문/빈칸 스타일을 사용합니다.
- 테마 전환의 과거 RGB/ANSI 값 치환을 제거했습니다. 배경·텍스트·트리·표의 역할과 현재 상태에서 스타일을 다시 적용합니다. 숨긴 SQL 탭도 갱신합니다.
- SQL 탭 버튼을 재생성하지 않고 다시 스타일링해 버튼에 있던 키보드 포커스를 유지합니다. SQL·암호 입력·선택·결과·스크롤·DB 작업 상태를 새로 만들지 않습니다.
- 미커밋 셀은 배경, 행 번호 `*`, 선택 셀의 ‘미커밋 셀 변경’ 안내를 함께 사용합니다. 표식은 표시 계층에만 두어 원본·복사·내보내기를 바꾸지 않습니다.
- 닫힌 화면/트리의 스타일 역할 정보는 정리해 보관하지 않습니다.

## 검증 범위

12프로필 × 67장면 × 한·영 × 초기/테마 왕복 = 3,216프레임을 기준으로 검증합니다. 한 쌍은 같은 화면에서 dark → light → blackwhite → 원래 테마로 변경한 결과입니다. 대비 검사는 tcell 참조 팔레트에서 글꼴 굵기만 변경하는 모델과 굵게=밝은색 모델을 각각 사용합니다.

일반 회귀 검사에는 다음을 추가했습니다.

- 12프로필의 본문·안내·입력·선택·버튼·비활성·수정 셀·그리드·SQL 문법색 대비.
- ANSI8/16의 허용 색상 인덱스.
- 실제 Form.AddTextView 설명문 렌더링의 대비.
- 복사창 제목의 실제 그리기와 테마 왕복.
- 활성 SQL 탭 버튼의 포커스·스타일·SQL 보존.

실제 SecureCRT·MobaXterm, 사용자 ANSI 팔레트 및 모든 작은 창 크기를 이 기록으로 검증 완료 처리하지 않습니다. 이번 변경은 렌더링/스타일이며 키맵·DB 드라이버·트랜잭션 처리 로직은 변경하지 않았습니다.

## 최종 로컬 검증 결과

- `make test`: 전체 `go test -race ./...` 통과.
- `make check`: `go vet ./...` 통과.
- `make build`: Linux ARM64 바이너리만 빌드. `--version`은 아직 v0.10.0입니다.
- 마지막 하단 버전 글자색 보완 후 관련 `-race` 검사·vet·ARM64 빌드도 통과했습니다.
- 3,216프레임 생성 통과. 초기/왕복 1,608쌍의 렌더링 차이 0건.
- 두 굵게 모델을 적용한 6,432개 분석 행에서 전경/배경 동일 및 4.5:1 미만 텍스트 후보 0건. Dim 배경·공백·장식선 제외 등 기존 분석기의 제한을 그대로 적용합니다. 이는 모든 실제 단말의 대비를 보장하는 수치가 아닙니다.
- 공통 역할별 참조 대비 최저 4.64:1.
- 회귀 테스트가 변경한 SQL/입력·포커스·복사 데이터 보존을 확인했습니다.
