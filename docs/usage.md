## 연결

일반 실행 시 접속 화면이 먼저 열립니다(`--demo`는 메인 화면으로 시작). **Alt+L** 또는 **세션 → 접속**(Alt+S, Enter)으로 다시 열어 Host, Port, Username, Password를 입력합니다. 연결 유형에서 **Service Name** 또는 **SID**를 선택하고 해당 이름을 입력한 뒤 **Ctrl+Enter / Alt+C** 또는 접속 버튼 클릭으로 연결합니다. 암호는 화면에서 가리며, 기본적으로 디스크에 저장하지 않습니다. 명시적으로 암호화 저장을 선택할 수 있습니다. 선택적으로 `LAZYORA_HOST`, `LAZYORA_PORT`, `LAZYORA_USER`, `LAZYORA_PASSWORD`, `LAZYORA_NAME` 환경변수로 입력 기본값을 지정할 수 있습니다. 암호를 명령행 인자로 받지 않습니다.

직접 입력칸은 **흰 배경**, 선택박스는 **어두운 파랑 계열 배경과 `v` 표시**로 구분합니다. 선택박스에 포커스가 있으면 청록색으로 강조합니다. 8·16색 터미널에서는 선택박스에 ANSI 파랑을 사용합니다.

접속 화면 위쪽 **저장된 접속 불러오기**에서 기존 프로필을 선택합니다. 아래 **접속 정보 편집**은 **별칭(Alias)**부터 시작합니다. **Alt+R**은 저장된 접속, **Alt+A**는 별칭으로 이동하며 **Tab/Shift+Tab**은 두 영역을 순환합니다. 목록의 **새 접속**을 선택하면 환경변수·기본값으로 돌아가고 비밀번호는 비웁니다.

**별칭(Alias)**을 입력하고 하단 **저장(Ctrl+S / Alt+S)** 버튼을 누르면 호스트·포트·사용자·접속 방식·Service Name/SID를 저장합니다. 실제 DB에 연결하지 않아도 저장할 수 있습니다. 같은 별칭은 기존 정보를 갱신하고, 다른 별칭은 새 접속으로 추가합니다. 다음 실행에서 **저장된 접속(Alt+R)** 목록으로 불러올 수 있으며 **Alt+A**로 별칭 입력칸을 선택합니다. 별칭을 바꾸어 저장하면 새 항목이 추가됩니다.

접속 정보는 UI 설정 파일과 같은 폴더의 `connections.json`에 저장합니다. Linux 기본 경로는 `~/.config/lazyora/connections.json`입니다. 기본적으로 **비밀번호는 저장하지 않습니다.** 저장된 접속을 선택하면 이전 비밀번호를 지우고, 암호화 저장을 사용한 접속만 잠금 해제 후 해당 비밀번호를 채웁니다. 저장 버튼을 누를 때는 현재 입력한 비밀번호를 메모리에 유지하여 바로 접속할 수 있습니다. **비밀번호 저장 (암호화)**을 선택하고 저장하면 별도 암호화 저장소에 보관합니다. **Alt+K** 또는 **도구 → 암호 관리**에서 잠금·마스터 변경·초기화를 할 수 있습니다. 자세한 사용법은 [암호 관리](credentials.md)를 참고하세요.

## 언어·마우스 설정

한 실행파일에서 English와 한국어를 지원합니다. **도구 → 설정**(Alt+T, Enter)에서 언어와 마우스 사용 여부를 선택하고 **Ctrl+S / Alt+S** 또는 저장 버튼으로 적용합니다. Esc는 변경을 취소합니다. 언어를 바꿔도 작성한 SQL, 조회 결과와 접속 화면의 입력값을 유지합니다. Oracle에서 받은 오류와 조회 데이터는 원문을 표시합니다.

저장된 언어 설정이 없으면 `LC_ALL`, `LC_MESSAGES`, `LANG` 순서로 처음 발견한 비어 있지 않은 값을 확인합니다. `ko` 로캘이면 한국어, 나머지는 영어입니다. 설정 파일 없음·언어 항목 누락·빈 값·null을 미설정으로 처리하며, 명시적으로 저장한 한국어·영어 설정은 로캘보다 우선합니다. 마우스는 기본으로 켜져 있습니다. 버튼·입력칸·결과 셀을 클릭하고 휠로 스크롤할 수 있습니다. 마우스를 껐을 때도 도구 → 설정에서 다시 켤 수 있습니다.

설정은 OS 사용자 설정 폴더의 `lazyora/settings.json`에 저장합니다. Linux 기본 경로는 `~/.config/lazyora/settings.json`이며 `XDG_CONFIG_HOME`을 따릅니다. `LAZYORA_CONFIG`로 파일 경로를 지정할 수도 있습니다. 언어와 마우스 설정만 저장하며 접속 정보는 같은 폴더의 별도 파일로 관리합니다. `LAZYORA_CONFIG`의 파일 이름을 `connections.json`으로 지정했다면 접속 파일 이름은 충돌을 피하도록 `connection-profiles.json`을 사용합니다. DB 비밀번호는 설정·접속 프로필 JSON에는 저장하지 않으며, 선택한 경우 별도 `credentials.enc`에 암호화하여 저장합니다. 저장에 실패하면 기존 설정을 유지하고 오류를 표시합니다.

## 스키마·객체 탐색

접속하면 왼쪽 브라우저 위에 **사용자·객체 종류 선택박스**, 아래에 **객체 목록**이 나타납니다. 기본 사용자는 접속 계정, 기본 종류는 테이블입니다. 사용자를 바꾸면 해당 사용자의 객체를 조회하고 종류를 바꾸면 해당 종류만 표시합니다. **Alt+U 사용자**, **Alt+O 객체 종류**로 이동하며 마우스로도 선택할 수 있습니다. 스키마 목록에는 `ALL_USERS`에 보이는 계정이 표시되지만 객체는 현재 접속 계정에 접근 권한이 있는 항목만 표시하므로 빈 스키마도 있을 수 있습니다. 탐색으로 접속 계정이나 현재 스키마를 변경하지 않습니다.

지원하는 분류는 **테이블, 뷰, 구체화 뷰, 함수, 프로시저, 패키지, 패키지 본문, 시퀀스, 동의어, 인덱스, 트리거, 타입, 타입 본문**의 13종입니다. 구체화 뷰의 저장용 테이블은 테이블 분류에 중복 표시하지 않습니다. 패키지·타입의 정의와 본문은 별도 분류로 표시합니다.

**Alt+B** 또는 **보기 → 스키마**로 스키마 창을 표시하거나 숨깁니다. 숨기면 SQL·결과 영역이 전체 너비를 사용하고, 다시 열면 기존 사용자·종류·목록·선택 상태를 유지한 채 탐색기로 포커스를 옮깁니다. 방향키 위·아래로 선택하고 **Enter 또는 클릭**으로 객체 상세를 엽니다. 테이블·뷰·구체화 뷰를 열면 컬럼명·데이터 타입·NULL 허용 여부·컬럼 코멘트를 별도 화면에서 확인합니다. 코멘트가 없는 컬럼은 빈칸으로 표시합니다. 그 밖의 객체는 스키마·이름·종류·상태를 보여줍니다. 함수·프로시저·패키지/본문·타입/본문·트리거는 **Alt+S**로 소스를 조회·편집합니다. 함수·프로시저·패키지/본문은 **Alt+A**로 인자·반환값·오버로드를 확인합니다. 소스 화면의 **F9** 또는 컴파일 버튼으로 수정 내용을 DB에 적용하거나 기존 객체를 재컴파일하고, 오류의 행·열·메시지를 확인합니다. 컴파일 전에는 DDL의 암시적 커밋을 경고하며, 적용하지 않은 편집 내용을 닫기·새로고침·종료로 버릴 때도 확인합니다. 마우스 휠로 목록을 스크롤할 수 있습니다.

탐색기에서 **Ctrl+R**은 스키마 목록과 선택 스키마의 객체를 새로 불러옵니다. 객체 상세에서는 **Ctrl+R**로 컬럼 또는 기본 정보를 다시 조회하고 **Esc** 또는 닫기 버튼으로 돌아옵니다. **Tab**은 SQL → 결과 → 표시 중인 사용자 선택 → 객체 종류 선택 → 객체 목록 순서로, **Shift+Tab**은 역순으로 이동합니다. 스키마 창이 숨겨져 있으면 포커스 이동 대상에서 제외합니다. F6으로 SQL과 결과 사이를 전환할 수도 있습니다.

탐색과 컬럼 상세는 작성 중인 SQL·조회 결과와 미완료 트랜잭션을 유지합니다. 메타데이터 조회도 기존 SQL 실행과 같은 백그라운드 작업으로 순서대로 처리하며 Esc로 취소를 요청할 수 있습니다. `--demo`에서는 DB 없이 샘플 객체 목록과 컬럼 상세를 살펴볼 수 있습니다. Oracle 10g에도 있는 사전 뷰의 컬럼을 사용했으며, 이번 기능의 실DB 검증은 Docker Oracle Free에서 진행했습니다.

## SQL 파일

**Ctrl+O 열기**, **Ctrl+S 저장**, **Ctrl+Shift+S 다른 이름으로 저장**, **Ctrl+N 새 SQL**, **Ctrl+W 닫기**를 지원합니다. 파일 메뉴에서도 선택할 수 있습니다. Ctrl+Shift+S를 구분하지 못하는 터미널에서는 **파일 → SQL 다른 이름으로 저장**을 사용하세요. 현재는 SQL 편집기 하나를 사용하며, 새 SQL·닫기는 빈 문서로 돌아갑니다.

파일 창에서 경로를 입력하거나 디렉터리·파일 목록을 선택합니다. 디렉터리는 Enter·클릭으로 이동하고 파일을 선택하면 경로를 채웁니다. 경로 입력 중 Enter, **Ctrl+Enter / Alt+Enter**, 또는 열기·저장 버튼으로 적용합니다. **Tab / Shift+Tab**은 경로·목록·버튼 사이를 이동하고 버튼은 좌우 방향키로 선택합니다. Esc는 취소하며 F1은 도움말입니다. 상대 경로는 현재 탐색 중인 디렉터리를 기준으로 하고 `~/`도 사용할 수 있습니다.

SQL 창 제목에 파일명과 **미저장 표시 `*`**가 나타납니다. 수정한 SQL을 새 문서·다른 파일 열기·닫기·종료로 버리기 전에는 **저장 / 버리기 / 취소**를 확인합니다. 기본 선택과 Esc는 취소입니다. 저장 경로 선택이나 덮어쓰기를 취소하거나 저장에 실패하면 후속 작업을 진행하지 않고 편집 내용을 유지합니다. 앱 종료는 SQL 파일 확인 후 기존 DB 종료 확인으로 이어집니다. **파일 저장은 DB 커밋이 아니며**, 파일을 버리는 선택도 DB 롤백을 실행하지 않습니다. 뒤의 DB 종료창에서 계속 사용을 선택하면 SQL 편집 내용도 유지합니다.

한글을 포함한 **UTF-8 SQL 파일(최대 16 MiB)**을 지원합니다. UTF-8 BOM과 LF·CRLF 형식을 보존하며, 줄바꿈이 섞인 파일을 수정하여 저장하면 첫 줄바꿈 형식으로 통일합니다. 수정 없이 같은 파일을 저장하면 원본 바이트를 유지합니다. NUL이 있는 파일·잘못된 UTF-8·심볼릭 링크는 열지 않습니다. 기존 파일 덮어쓰기와 외부 수정·삭제 감지는 별도 확인을 거칩니다. 외부 프로그램의 저장과 완전히 동시에 발생한 변경까지 잠그지는 않습니다.

저장은 같은 디렉터리의 임시 파일을 작성한 뒤 교체하며, 기존 파일의 권한 비트를 유지하고 새 파일은 소유자 읽기·쓰기 권한으로 만듭니다. 부모 디렉터리는 미리 있어야 합니다. 읽기 전용 파일·잘못된 경로·쓰기 실패는 오류를 표시하며 편집 내용을 유지합니다. 다른 LazyOra의 동시 저장은 `<파일명>.lazyora.lock`으로 막습니다. 비정상 종료 후 이 파일이 남아 저장이 막히면 해당 파일을 저장 중인 LazyOra가 없는지 확인한 뒤 잠금 파일만 제거하세요.

## 위험 SQL 실행 확인

메인 편집기에서 DDL과 **최상위 WHERE가 없는 UPDATE·DELETE**를 실행하면 사유와 실제 실행 대상 SQL을 먼저 보여줍니다. 선택한 SQL이 있으면 그 선택 부분만 확인합니다. 기본 선택은 **취소**이며 Enter 또는 Esc로 취소합니다. 실행 버튼을 방향키·Tab으로 선택한 뒤 Enter를 누르거나 마우스로 클릭해야 제출합니다. 취소하면 SQL·조회 결과·트랜잭션·실행 이력을 바꾸지 않습니다.

Tab으로 SQL 미리보기와 버튼을 순환하고 방향키·PgUp/PgDn으로 SQL을 읽습니다. F1 도움말을 닫으면 확인 화면으로 돌아옵니다. 확인창에 표시한 SQL을 그대로 제출하며 나중에 편집기 값이 바뀌더라도 다른 SQL을 실행하지 않습니다. 소스 적용·컴파일은 기존 DDL 확인창을 사용합니다.

주석·문자열·따옴표 식별자·서브쿼리 안의 WHERE는 바깥 UPDATE·DELETE의 조건으로 보지 않습니다. 조건을 확실히 검사하지 못한 UPDATE·DELETE도 확인합니다. DDL·관리 명령은 CREATE·ALTER·DROP·TRUNCATE·RENAME·COMMENT·GRANT·REVOKE·PURGE·FLASHBACK·ANALYZE·AUDIT·NOAUDIT·ASSOCIATE·DISASSOCIATE·UNDROP을 대상으로 합니다.

이 검사는 영향 행 수나 조건의 선택도를 판단하지 않습니다. **WHERE 1=1처럼 조건이 있어도 전체 행이 바뀔 수 있으며**, PL/SQL·동적 SQL·프로시저 내부 SQL·MERGE는 분석하지 않습니다. 경고가 없다는 뜻이 안전하다는 뜻은 아닙니다. Oracle DDL의 암시적 커밋과 ALTER SESSION/SYSTEM 등 관리 명령의 실제 동작은 명령에 따라 다릅니다. [Oracle SQL 분류 안내](https://docs.oracle.com/cd/B13789_01/server.101/b10759/statements_1001.htm)를 참고하세요.

## 조작

상단 메뉴는 파일·편집·세션·실행·보기·도구·도움말입니다. Alt+F/E/S/X/V/T/H로 각각 열고, 좌우로 메뉴 전환, 위아래로 선택, Enter로 실행, Esc로 닫습니다. 마우스로도 사용할 수 있습니다. 현재 사용할 수 없는 항목은 흐리게 표시하고 실행하지 않습니다. 메인 단축키·메뉴·F1 기본 명령 목록은 공통 정의를 사용합니다.

기능키는 [Toad 공식 단축키 안내(pp. 24–26)](https://i.dell.com/sites/csdocuments/shared-content_data-sheets_documents/en/guidetousingtoadfororacle.pdf)를 기준으로 배정합니다. **F2 쿼리 전체화면**, **Shift+F2 결과 전체화면**, **F6 쿼리/결과 전환**, **F7 SQL 전체 지우기**, **F8 SQL 이력**, **F10 문맥 메뉴**를 지원합니다. F7은 확인 후 지우며 실행 취소(Ctrl+Z)로 복원할 수 있습니다. 이력은 이번 앱 실행에서 제출한 SQL을 최대 100개까지 메모리에 보관하며 디스크에 저장하지 않습니다. 이력을 불러올 때 현재 SQL이 있으면 덮어쓰기를 확인하고, 자동으로 실행하지 않습니다.

**Ctrl+F 찾기**, **F3 다음 찾기**, **Shift+F3 이전 찾기**, **Ctrl+R 바꾸기**는 쿼리 편집기의 일반 문자열을 대소문자를 구분하여 찾습니다. 끝에 도달하면 순환합니다. F4는 선택한 객체 또는 커서 아래 객체의 상세를 열고, Ctrl+D는 객체명을 입력하는 상세 조회 창을 엽니다. F9·Ctrl+Enter·Shift+F9로 선택한 SQL을 실행하며, 선택이 없으면 편집기 전체를 한 문장/PLSQL 블록으로 실행합니다. Toad의 문장 자동 구분·스크립트 실행·디버거는 아직 구현하지 않았습니다. **F5 스크립트·Ctrl+F9 구문 검사·F11 디버거 계속 실행**은 미지원 상태로 예약하며 DB 명령을 실행하지 않습니다.

전체화면에서 같은 키를 다시 누르면 분할 화면으로 돌아오고, 다른 창의 전체화면 키나 F6으로 표시할 창을 바꿉니다. **보기 → 창 최대화 / 복원**은 메뉴·상태·푸터를 유지하는 기존 최대화 기능입니다. 전체화면에서 F1 도움말이나 Alt+M 메뉴를 열면 임시로 일반 화면을 표시하고, 닫으면 전체화면으로 돌아갑니다. 스키마 표시·숨김은 Alt+B 또는 보기 메뉴를 사용합니다. 접속은 Alt+L 또는 세션 메뉴, 설정은 도구 메뉴에서 엽니다. Alt+C/Alt+R 커밋·롤백, Alt+Enter 실행, Ctrl+Q 종료는 LazyOra의 터미널용 추가 배정입니다.

결과는 **Ctrl+C 셀/범위 복사**, **Alt+Y 행 복사**, **Shift+방향키·마우스 드래그 범위 선택**을 지원합니다. 원본 값을 TSV로 클립보드에 전송 요청하며 미지원 터미널에서는 **편집 → 복사 내용 보기**로 터미널 기본 선택·복사를 사용합니다. 자세한 동작과 제한은 [터미널·복사 안내](terminal.md)를 참고하세요.

화면 최하단의 단축키 안내는 현재 포커스에 따라 바뀝니다. SQL 편집기에서는 `F9 / Ctrl+Enter` 실행과 전체화면 전환을, 결과 표에서는 셀·범위·행 복사와 이동을 표시합니다. 키보드나 마우스로 포커스를 바꾸면 즉시 갱신되며, 접속·설정·도움말에서는 해당 화면의 저장·닫기·스크롤 동작을 안내합니다. 하단 버튼을 클릭해도 해당 단축키와 같은 동작을 실행합니다. 버튼에 포커스가 있으면 **좌우 방향키**로 같은 줄의 버튼을 순환하고 **Enter**로 실행합니다. 폼과 상세화면의 버튼은 Tab/Shift+Tab으로 접근하며, 선택된 버튼은 **진한 파랑 배경·흰색 굵은 밑줄 글자**로 구분합니다(8/16색 포함). F1 도움말은 현재 화면의 조작을 먼저 보여주고 SQL·결과·화면/메뉴/버튼·접속/설정·스키마/소스·트랜잭션·터미널/지원 범위·앱 정보로 나눕니다. **0~8**로 항목에 바로 이동하고 방향키·PgUp/PgDn·마우스 휠로 스크롤합니다. F1 또는 Esc로 닫으면 이전 화면과 포커스로 돌아갑니다.

메인 화면의 **Alt+C 커밋·Alt+R 롤백** 버튼은 SQL 편집기·결과 표의 포커스에 관계없이 항상 표시하며 마우스로도 실행할 수 있습니다.

기본 색상은 [Nord 팔레트](https://www.nordtheme.com/docs/colors-and-palettes/)를 참고했습니다. SQL·폼 입력칸은 흰색 계열 바탕과 어두운 글자, 버튼은 청회색, 선택·포커스는 청록색으로 구분합니다. 하단 단축키 영역은 별도 청회색 배경으로 표시합니다.

8색·16색 터미널에서만 입력창 테두리를 파랑, 결과·대화창 테두리를 청록으로 구분하며 포커스가 있는 창의 선을 굵게 표시합니다. 256색·True Color에서는 기존 테마를 유지합니다. SecureCRT에서 RGB 색상 명령을 처리하지 못하면 `TCELL_TRUECOLOR=disable ./lazyora-linux-amd64`로 터미널의 기본 팔레트를 사용해 시험할 수 있습니다.

일부 SecureCRT 세션은 기본 커서 모양 제어문자(`ESC[0 q`)의 마지막 `q`를 화면에 출력합니다. LazyOra는 이 명령을 보내지 않고 터미널의 기존 커서 모양을 유지합니다. 커서 이동·표시·숨김과 키보드·마우스 입력은 그대로 동작합니다.

Ctrl+Enter는 터미널이 Ctrl 조합을 구분해 전달할 때 동작합니다. 일반 Enter와 같은 입력으로 전달되는 환경에서는 Alt+Enter 또는 F9를 사용합니다. SecureCRT 매핑 방법은 [터미널 안내](terminal.md)를 참고하세요. 도움말은 접속 화면에서도 열 수 있으며 F1 또는 Esc로 닫으면 이전 화면과 입력 위치로 돌아갑니다.

정상 종료를 요청하면 항상 확인 팝업을 표시합니다. 변경 가능한 SQL을 실행한 후 앱에서 커밋·롤백하지 않은 내역이 있으면 **커밋 후 종료 / 롤백 후 종료 / 계속 사용**을 선택합니다. 변경 내역이 없어도 **종료 / 계속 사용**을 확인합니다. 기본 선택과 Esc는 계속 사용이며 기존 화면·SQL·조회 결과를 유지합니다. 실행 중이면 취소를 요청한 뒤 작업이 끝나면 종료를 확인합니다. 커밋·롤백 처리 실패 시 종료하지 않고 재접속하여 DB 처리 결과를 확인하도록 안내합니다.

종료창은 추적 중인 실행 건수와 최근 SQL을 보여줍니다. **내역 보기(Alt+V)** 또는 **세션 → 미커밋 내역 보기**에서 실행 시각·SQL·처리 행 수·성공/오류를 확인합니다. 목록에서 선택하면 원문 SQL을 보여주며 Tab으로 SQL 영역에 이동해 스크롤하고 Ctrl+C로 상세를 복사할 수 있습니다. Esc로 종료창에 돌아가도 커밋·롤백하지 않으며 기본 선택은 계속 사용입니다.

기록은 마지막으로 성공한 앱 커밋·롤백 이후 변경 가능 SQL과 소스 적용·컴파일을 대상으로 합니다. SELECT·메타데이터 조회는 제외하고 실행 실패·취소도 결과 확인이 필요할 수 있어 기록합니다. 커밋·롤백 성공 또는 새 접속 시 비우며 실패 시 보존합니다. 최근 100개를 메모리에만 보관하고 이전 생략 건수를 표시합니다. SQL 하나는 앞부분 64 KiB까지만 보관하며 잘림을 표시합니다. **행별 변경 전·후 비교나 실제 DB 미커밋 목록은 아닙니다.**

미커밋 안내는 앱의 실행 내역을 보수적으로 추적합니다. 단순 SELECT·스키마 탐색은 변경으로 표시하지 않으며, DDL·PL/SQL 내부 커밋이나 변경 가능 SQL의 실행 오류 이후에는 실제 DB 트랜잭션과 차이가 있을 수 있습니다. 강제 종료·접속 단절에는 확인 팝업을 보장하지 않습니다.

SELECT와 WITH 조회는 결과 표로 표시합니다. 결과는 최대 1,000행까지 가져옵니다. DML은 수동 커밋 방식입니다. **Oracle DDL은 암시적 COMMIT을 발생시킬 수 있습니다.** PL/SQL 프로시저 내부 COMMIT도 Oracle의 동작을 따릅니다. 재연결에 성공하면 이전 연결을 롤백하고 닫습니다. 실행은 백그라운드 작업으로 처리하며 60초 제한과 취소 요청을 적용합니다. 드라이버·네트워크 상태에 따른 취소 동작은 실DB 검증이 필요합니다.

한 번에 SQL 한 문장 또는 `BEGIN`/`DECLARE` PL/SQL 블록 하나를 실행합니다. 일반 SQL 끝의 세미콜론은 제거하고 PL/SQL 내부 세미콜론은 유지합니다. PL/SQL 끝의 별도 줄 `/`는 제거합니다. 메인 SQL 편집기에서 SQL*Plus 스크립트, 여러 문장 일괄 실행, CREATE PROCEDURE 스크립트, 바인드 변수 입력, REF CURSOR/DBMS_OUTPUT 출력은 아직 지원하지 않습니다. PL/SQL 객체의 생성·수정은 스키마 탐색기의 소스 편집·컴파일 화면을 사용합니다. 현재 LOB 표시와 대형 단일 셀 메모리 사용량도 추가 검증이 필요합니다.
