LazyOra v0.6.0은 Oracle SQL·PL/SQL 구문 색상과 SQL 탭·편집 메뉴를 추가하고, 접속·설정 저장·긴 SQL 처리의 안정성을 개선합니다.

## 변경 사항

- SQL 탭과 PL/SQL 소스 편집기에서 키워드·함수·타입·문자열·숫자·주석·바인드를 구분합니다. 8·16색 터미널에서도 구문 색상을 제공하고 선택 영역 강조를 우선합니다. 저장·실행하는 SQL 원문은 그대로 유지합니다.
- **SQL 탭(Alt+G)** 메뉴에서 새 탭·현재 탭 닫기·다음·이전 탭을 선택합니다. 편집 메뉴에는 실행 취소·다시 실행·잘라내기·붙여넣기·SQL 전체 선택을 추가했습니다. 스키마 새로고침과 문맥 메뉴도 보강하고 긴 메뉴는 터미널 높이에 맞춰 스크롤합니다.
- 재접속 시 미커밋 변경의 커밋·롤백·취소를 확인하고, 연결 실패·취소 시 기존 연결과 트랜잭션을 보호합니다. 트랜잭션 처리 결과를 알 수 없는 세션은 별도 안내합니다.
- 여러 인스턴스의 접속 목록·암호 저장 충돌을 검사해 조용한 덮어쓰기를 방지합니다. 사용자 지정 설정 파일명이 Connections.json처럼 대소문자만 달라도 접속 목록과 경로가 겹치지 않도록 합니다.
- 도움말에서 Esc로 돌아올 때 진행 중 SQL·내보내기를 취소하지 않습니다.
- 긴 SQL의 행 번호와 단독 / 구분 분석을 선형으로 개선했습니다. Linux ARM64 시험에서 8만 문장 분석이 약 3.16초에서 83ms로 줄었습니다. 환경에 따른 측정값이며 모든 환경의 속도를 보장하지 않습니다.
- 시험용 `test/oracle/run.sh`로 실행한 앱을 종료하면 Oracle Compose도 자동으로 내려 메모리를 반환합니다. DB 데이터 볼륨은 보존하며, 앱 오류 종료 시에도 정리를 시도합니다.
- README에 Toad와 같은 Oracle 작업 흐름을 터미널에서 제공한다는 프로젝트 목표를 명시했습니다.

## 검증과 범위

Linux ARM64에서 전체 race 테스트·vet·기본 빌드를 통과했습니다. 구문 색상은 UTF-8·줄바꿈·선택·스크롤·undo와 SQL 원문 보존을 검증했고, Oracle Free 및 실제 터미널 시험을 수행했습니다. 메뉴는 한영 탭 조작·미저장 SQL 보호·복사·undo와 80×10 화면 스크롤을 검사했습니다. Windows/macOS CI에서는 설정 파일 경로 충돌과 빌드·버전 실행을 확인합니다. 실제 CentOS·Oracle 10g 및 Windows/macOS TUI 전체 재시험은 이번 배포의 검증 범위에 포함하지 않습니다.

Vim·Notepad++ 키맵, 여러 DB 동시 접속, 결과 그리드 디자인 개선과 객체·컬럼 자동 완성은 후속 작업이며 이번 버전에 포함되지 않습니다.

## 다운로드

Linux·Windows·macOS AMD64/ARM64 실행파일 6종과 LICENSE·README.md·TVIEW-LICENSE.txt·SHA256SUMS를 제공합니다. Go나 Oracle Instant Client를 별도로 설치하지 않습니다. Linux·macOS는 chmod +x로 실행 권한을 부여하세요.
